# 公共商品区域与数量选价

2026-10-28。Gin 公共商品列表及原 ID 详情接受可选 region_id、quantity。没有 region_id 时保留纯目录读取，所有变体 calculated_price 为 null，pricing=false。显式有效区域开启 pricing=true；quantity 默认 1，必须为规范的正整数，最高 1000000000，单独 quantity、币种/渠道/客户群覆盖、重复或未知参数均 400。不存在/已删除区域 404。

币种来自有效区域，且必须在服务端明确绑定店铺的有效币种列表和有效 currency 主记录中唯一存在；缺配置、重复或失效 503。店铺渠道、发布状态、完整选项归属及商品可见性继续应用。不完整变体不选价，不因已配置价格推断可售。匿名查询不读取员工/客户 cookie，不接收客户端客户群；客户身份接入和交易鉴权仍未完成。

## 选择语义

内部 pricing 包由只读事务装载正式关联和纯函数 Select 组成，独立于 Medusa 运行时。当前价格、价格规则、价目表及规则、含税偏好通过 catalog_variant_price_sets/pricing_* 读取；共享 price set 只计算一次。缺失/删除关联或集合不提供报价，多有效集合的模糊变体整体 503，不能任意选择一个。

金额及数量边界复用 totals.Number/Resolve 的 raw 优先规则，精确十进制比较，金额保持主货币单位字符串，不经 float64 或乘除 100。raw JSON 重复/额外/缺失键、无效 precision、负金额、无界或非法数字失败；不能在损坏 raw 时退回 scalar。数量区间两端含边界，负边界或 min>max 拒绝。缺价与真实零价分别为 null 和字符串 "0"。

依据本地已安装 2.21.2 pricing/repositories/pricing.js、services/pricing-module.js 的实际行为：先按匹配规则数量排序，再按金额升序，同分同价用原 ID 稳定排序；价目表额外计入表规则数量。只有规则数量与全部当前有效规则一致才允许匹配。支持来自可信上下文的 region_id、sales_channel_id 和 customer.groups.id 的等值条件；价目表条件接受 JSON 字符串或有界字符串数组。未知属性、无法匹配的条件、非等值身份条件、计数不一致、缺失/删除价目表不进入候选。当前 HTTP 不提供客户身份或任意数值规则上下文。

仅 active 且时间区间有效的价目表参与，起止边界均含端点。当前最高排序表价为 override 时覆盖基础价，包括提高价格；为 sale 时与所选基础价取较低值。原价参考优先匹配的非促销 override，再退到基础价；因此促销叠加覆盖价时保留对应原价。此规则跟随已安装服务，不把“所有价格直接取最低”当作实现。明确修正旧 JS 真值判断的零价问题：零基础价不会被正数促销价替代。

含税标记沿用实际偏好规则：只有价格匹配 region_id 规则且存在区域偏好时用区域偏好，否则用币种偏好，再否则 false。重复有效偏好导致 503。此标记描述价格配置，不计算税额，不代替税务引擎或支付总额。

## 响应与边界

calculated_price 返回 calculated_amount、nullable original_amount、currency_code、两种含税标记、两种价目表标记，以及 calculated_price.price_list_type。内部选中价格/集合 ID 保留供未来服务端购物车事务使用，但不序列化公开；规则、表标题/描述/metadata、raw JSON 不返回。

整个商品读取继续用 Repeatable Read，只读取已验证完整变体。单次最多 10000 个有效变体关联，价格/价格规则/价目表/表规则共同最多 20000 行，偏好最多 100 行；超限整体 503，不能先分页价格再挑选。成功公共重验证；错误 no-store；没有写入、预留或支付操作。availability/checkout 仍为 false。

## 验证与剩余

[人工 MySQL/Redis 报告](admin-auth-report.json) store_pricing 验证真实 Gin 路由中的区域币种、数量端点、规则具体度、sale/override 原价关系、共享集合、不完整变体、未知条件、缺价、损坏 raw、含税偏好、私有字段、规则超限和只读指纹。纯函数测试补充精确大额/低位小数、零价、时间区间、可信客户群、规则计数和稳定同价。

[固定来源报告](catalog-mysql-rehearsal-report.json) 对实际 30 个公开商品、1558 个有效变体，在 1 区域的数量 1/2 两个上下文中，比对 3056 个有效报价及 60 个不完整变体未报价结果。独立 Node 工具读取已钉住私有来源，在无 DB/网络/服务启动条件下调用安装的旧价格服务，对照原价/现价、币种、价目表及含税标记；原始输入及输出仅在独占容器 tmpfs，最终公开报告仅数量和源码哈希。固定来源无活动价目表，表类型行为由人工 SQL 和纯函数另外验证，不虚称真实样本已覆盖该情形。

[真实浏览器报告](admin-live-report.json) 验证显式店铺币种的区域查询、未知区域/币种覆盖拒绝、不完整配置仍为 null，再回归 Ant 后台和 Astro SSR。选价不等于全量交易验收：地址/客户规则扩展、客户身份、数量可售、税/优惠/配送、购物车、checkout、逐键展示 metadata 和 Astro 实际页面仍需继续；前台尚不能使用旧 number helper 直接展示精确字符串，必须完成独立 adapter。
