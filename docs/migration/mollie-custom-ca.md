# 支付渠道的显式 CA 配置

macOS 的 Go 使用系统钥匙串，不能把 Linux 下的 SSL_CERT_FILE 视作跨平台信任配置。新增可选服务器环境变量 `MOLLIE_CA_FILE`，由 checkout、补款、退款及通知进程共用的 checkoutconfig.Load 读取。未设置时保留现有平台证书信任与客户端行为。

文件最多1MiB，须包含有效 PEM 证书；读取失败、超限或无法解析时配置失败关闭，返回固定错误，不打印路径/内容。证书加入平台信任池，构造渠道客户端时再复制；保持固定 api.mollie.com 目标、HTTPS、主机名校验、禁止重定向及原 POST 不自动重试规则。TLS 最低1.2，没有跳过证书检查。受信任代理/隔离渠道使用显式证书文件，不安装系统证书或修改全局 HTTP 信任。

真实本机 TLS 单测覆盖正确证书/主机名成功，以及仅平台信任、无关 CA、错误主机名均拒绝；配置单测覆盖缺省、有效文件、缺失/坏文件/超限。完整、未适配命名空间且保留原业务来源文件的隔离检出 Go 全包与相关 vet 通过。先在缩小的本机联合快照运行全包时，原来源文件缺失及故意无效 namespace 测试被环境替换导致失败；没有放宽断言，改在完整检出验证。

报告 `mollie-custom-ca-report.json` 绑定本批五份源码及独立测试日志。完整23组SQL尚未在本次CA修改后复跑：Docker runner 在磁盘不足2GiB时禁止启动。此前67f4af6的23组SQL是历史证据，不能记作本批新代码已全量SQL验收。实际生产CLI与四新客户补款再退款联合正等待本机专有资源重跑，不能用 TLS 单测替代该连续链；不涉及真实渠道付款或邮件。
