# 订单邮件任务查看与人工恢复

在新 React Admin 的通知邮箱页面加入 Ant Design 任务表、状态、失败代码、尝试次数和确认重试。只读用户可查看，具有 mail.write 权限的员工可恢复失败任务。列表只返回任务元数据，不返回收件人、密钥、密文正文、发件配置指纹或提供方响应。

Gin 提供 GET /api/admin/notification-mail/order-jobs?offset=0 与 POST /api/admin/notification-mail/order-jobs/:id/retry。沿用管理员认证、私有缓存头和写入 Origin/CSRF 校验。重试需原任务次数与 operation_id；事务锁定任务及发送记录，只恢复首次尝试后23小时以内且无有效租约的失败任务。原正文、编号和发件配置指纹保持不变，因此发件配置变化等故障仍须恢复原配置后才可能发送。重新排队将本轮尝试次数归零，不延长首次尝试的恢复时限。

审计记录同时保存命令回执。相同操作并发或丢响应重试返回原结果；已发送任务不会因重放再次排队。每次重放重新校验当前权限。审计写入失败时任务状态一起回滚。前端结果不明时保留同一操作编号，禁止切换另一任务；刷新仍保留本次待确认操作。关闭页面后不持久保存此命令，重新进入会读取当前任务状态。

验证：独立 HEAD 源码快照仅加入本次五个后端文件，48项迁移，go test ./... 通过；隔离 MySQL/Redis AdminAuthentication 用例通过，包含受限投影、CSRF/Origin、重复/空字段、同操作并发、已发送回放不重排、恢复时限、有效租约、末尾审计失败回滚和撤权后回放拒绝。新 Admin 类型检查通过。浏览器使用真实 React 页面和合成 API，覆盖中英、390/1440宽度、失败后同操作恢复、过期禁用、403和只读权限；此证据不等于 Gin/MySQL 与浏览器联合验收。原邮箱配置浏览器回归通过。未向外部发送真实邮件。

仍缺真实收件、全站购物与配货联合验收，以及回收/售后通知。任务页面的“服务已接收”仅表示邮件提供方接受请求。
