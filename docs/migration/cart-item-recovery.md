# 原购物车数量和移除接入 Gin

2026-10-28。T032 / T039 的局部实现，完整购物车、结账及生产页面尚未验收。

`retail/storefront/src/components/cart/gin-cart.tsx` 在原 CartTemplate 外读取私有 current/view；SSR 与首次水合不输出私有购物车、凭证或可用写操作。初始化失败显示错误和明确重试，不当作空车。实际渲染沿用原 DOM、CSS、中英文本、数量输入、整车 busy、行错误及移除/空车状态；现阶段 checkout 继续关闭，当前变体观察尚待接入。

`cart-item-commands.ts` 与商品加购共用一个 Web Lock 和浏览器意图键。数量命令使用用户所见版本和绝对数量，零表示移除；不因 current 已更新就自动升级旧页面版本。不同标签页串行进入同一个写边界；同一实例重复点击合并，其他并行操作拒绝。外来地区、其他命令格式、损坏或不可写存储不会覆盖既有意图。

意图只保存格式、阶段、地区/币种/语言、购物车/行 ID、绝对数量、版本与原操作 UUID，不保存 cookie、CSRF、地址或价格。发出 POST 前写入并读回验证。响应丢失保留原意图；成功收到回执后先持久记录 refresh 阶段，再读取当前展示。刷新失败的恢复只执行 GET。确定拒绝只清除本次新建意图，已有不确定意图不会被失败重放自动丢弃。

恢复需用户明确点击。页面刷新只读取当前状态并提示待恢复，不自动提交。恢复仍核验当前持有凭证和地区/币种，并使用原 UUID、版本、行和数量；成功取得不早于当前/回执版本的完整展示后才清除意图。页面读取与正在执行的本地命令用代数及 busy 引用隔离，storage 事件不能在本地写入中覆盖页面状态。

验证分别记录在 `cart-client-report.json`（人工协议、单元、类型/build）、`astro-runtime-report.json`（原组件对照）和 `admin-live-report.json`（真实 Gin/MySQL/Redis）。真实 commerce fixture 使用原购买按钮导航到实际 GinCart；数量增加、丢失已提交数量响应、刷新后明确同键恢复、移除响应丢失后空车恢复均核对持久回执。人工注入只丢弃已成功返回的真实响应，不制造成功业务结果。是否通过以报告源码 SHA 与本次代码一致为准。

正式页面、全局导航/字体/布局、当前变体加载、地区切换、客户账户/合并、完整税费促销配送和下单支付仍待完成；本实现不修改旧服务或连接旧数据库。
