# Go 配送规则匹配

2026-10-28：`fulfillment.MatchRules` 是独立纯函数，供后续服务器配送资格协调器使用；不接受客户端自行声明的资格，也不授予配送、报价或 checkout 能力。

承接全部八种原运算符、默认 AND/可选 OR、空规则、布尔值规范化、严格字符串相等、in/nin 不转换数组元素、缺失值负向匹配。嵌套字段沿用原 picker 的标量停止、数组映射/展开/逗号拼接语义；数组里的 null 继续访问属性时返回错误，避免把原会抛错的上下文变成合格结果。先验证全部规则，不以提前短路掩盖坏配置；输入不变。

范围比较支持精确十进制/指数、空白及空字符串的零、前导加号/零、小数点、无符号十六/二/八进制。金额由服务器以精确字符串组装，数值规则阈值也不经 float64；JSON 数字上下文仅为承接原 Number 字符串化，不能用它承载精确金额。修正两项已登记边界：false/0 不再被真假值校验拒绝；超过 JS Number 精度的金额比较按真实值判断。

日期支持有时区的 ISO RFC3339 和 UTC 日期，比较截到原 JS Date 毫秒精度。不猜测服务器本地时区的无时区日期、自然语言日期、Infinity 或超出金额解析预算的数字；这些范围比较返回不匹配。**扩展原 Date.parse 其余形式、确认实际配置范围仍待完成**，当前不能声称任意旧规则文本完全兼容。

`node retail/scripts/capture-shipping-rules.cjs --check` 直接执行已安装旧模块纯函数，固定45组人工样例和四个来源文件SHA；不初始化服务、数据库或provider。Go测试读取该证据，另外覆盖高精度、false/0、非法输入与嵌套null拒绝。`go test ./...`、`go vet ./internal/fulfillment`、`go build ./cmd/...` 用于本批验证；数据库专项不会由纯函数测试替代。
