# 购物车数量修改与删除

2026-10-28。Gin 在已有 0027 草稿行项目能力上增加绝对数量命令，不新增或修改数据库迁移。继续要求当前匿名持有凭证、精确 Origin、CSRF、店铺/渠道归属和默认关闭的能力；不迁移旧购物车权限。

`POST /api/store/carts/:id/line-items/:line` 接受 `{"version":"2","quantity":"1"}`，UUIDv4 操作键放在 `Idempotency-Key`。只接受规范字符串，数量范围 0—1,000,000,000；0 明确表示移除。客户端不传 variant、价格、库存、客户或店铺。回执仍为 cart_id、version、line_id、quantity、replayed，版本准确增加一次；它是历史操作证据，后续状态须重新读取。

`cart.SetItem` 复用加购的同一 MySQL 事务与锁序，正数量按目标行的实际 SKU 和最终绝对数量重新选阶梯价，并检查整车共享库存。未知行、其他车的行和已删除行不允许新命令操作。与加购共用 cart+操作键命名空间，但命令摘要明确包含种类、目标行和原始请求；同键换数量、行或操作种类均冲突。已有加购摘要保持原样。

删除采用软删除，保存原数量、成交价快照、税行和折扣关系；金额读取排除已删除父行。删除不需要重新报价，不因商品下架或其他行不可购买而阻止清理购物车；删除回执的 price_id/price_set_id 为空字符串，不伪造新的价格证据。当前授权、版本和持久回执检查仍执行。修改、版本及回执必须一起提交，失败整体回滚；不预留或扣减库存。

Astro 的 `CartClient.setItem` 使用同源私有 Cookie 协议，严格校验请求和成功回执的目标行、绝对数量、版本及字段集合。网络或不可信成功响应保留不确定结果，不自动重试或换操作键。本批没有把修改/删除挂载到生产购物车页面，也没有新增修改操作的跨标签意图恢复界面。

## 验证

真实自有 MySQL/Redis 与 Gin HTTP 专项覆盖正数量重定价、零数量移除、同键八路单次提交、改请求冲突、越权/未知行、超库存、无凭证/CSRF、严格字段、撤销后拒绝；删除的后置回执 SQL 故障保持原行及版本，商品改为草稿后删除仍成功。完整后端数据库回归、Go 全量测试与 vet 通过；源码 SHA 以 admin-auth-report 和 cart-runtime-report 为准。

CartClient 共 39 项单元及独立类型/build、人工 HTTP 浏览器协议检查通过，见 cart-client-report。真实浏览器整组结果以 admin-live-report 的 absolute_quantity_and_removal 和源码 SHA 为准：同一车先经过加购/响应丢失恢复，再修改为 1（version 5）、移除为 0（version 6）及同键重放，读取空行与精确零合计。SQL 要求保留删除行原数量 1 和精确 raw 单价 100.000000000000000000001，库存预留为零。
