# 结账优惠码提交与原界面

原前台来源为 `medusa-store/apps/storefront/src/modules/checkout/components/discount-code/index.tsx`。新 Astro 结账摘要复用原表单、优惠标签、移除按钮及CSS，替换此前被禁用的优惠码占位；不改变其他页面外观。原行为是提交完整代码集合，自动优惠仍由服务端计算，未实际应用的代码提示不适用。

Gin 新增当前购物车私有 GET/POST `/api/store/carts/:id/promotions`。读取仅返回同一授权快照下的版本及已保存优惠ID、代码和自动标记；不公开规则、预算、客户属性或营销配置。POST只接受版本和代码数组，以当前购物车凭证、Origin、CSRF及稳定操作ID执行替换；重复字段、未知字段、null数组、控制字符、超量代码和非规范版本均拒绝。写请求独立限流32次/窗口。

提交事务先锁定当前归属及版本，读取原操作收据恢复重试；首次执行刷新商品快照、价格、现有人工固定运费、税费和优惠，核对总额后一起提交新版本与不可变收据。未知代码或末尾写收据失败会全事务回滚。自动优惠不会因客户移除手动优惠而消失；购物车阶段不登记活动预算使用。已有支付集合时拒绝新的修改，绝不通过删除付款记录模拟渠道作废；已有成功操作仍可恢复其收据。

迁移0051新增独立命令开关与收据表，默认关闭，须在独立运行配置明确启用；本轮未修改任何实际数据库配置。已提交迁移总数从49增至50，相关演练计数同步；工作区未提交0037支付通知改动仍保留且不夹带本次提交。

前端提交前保存操作描述（购物车、版本、操作ID、代码），没有客户信息、支付URL或凭证；失败不擅自换操作ID。已确认提交则先持久化“刷新”阶段，重试只重新读取一致版本的联系人、商品金额和优惠。未确认状态阻止地址/配送/付款继续提交，刷新后仍可恢复原操作；其他购物车命令也会检查优惠描述，付款开始后优惠输入禁用。更新优惠保留未提交的地址表单值。
