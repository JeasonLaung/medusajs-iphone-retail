# 商品加购协调与不确定操作恢复

2026-10-28。新增 `cart-commerce.ts`，向原ProductActions的ProductCommerce边界提供真实CartClient适配，不改写原组件CSS/文案/反馈。生产调用仍须显式enabled；默认catalog checkout=false不能自动开启购买。

每次新用户操作先在浏览器独占Web Lock内读取current；当前车必须同地区/币种，否则拒绝，尚不隐式换区。无车时明确开启创建scope，并在创建前保存稳定操作。创建成功后保存add阶段的原车ID/版本/UUID，随后提交；回执成功进入refresh阶段，读取当前授权和保存合计，汇总数量后才清除记录。刷新读失败只重读，不再发加购。

同实例并发相同点击共用一次Promise，不同配置并发拒绝。跨页面/标签经Web Locks串行，并共享单一localStorage意图槽。这里新增存储的是恢复意图，不是身份/交易事实；字段仅format/阶段/region/segment/variant/quantity/operation/cart/version及创建scope的SHA-256绑定，不存cookie、CSRF、凭证、价格、地址或用户信息。JSON长度/字段/规范字符串严格校验，损坏记录不静默丢弃。写存储和回读一致后才POST，存储不可用不提交。

不确定POST保留原意图，刷新后同配置重放原键。已有待完成意图时不同商品/地区不执行新命令。新请求明确HTTP拒绝可在下次用户点击重新读取版本；恢复不确定请求期间即使401/404也保留记录，不能推断旧操作没提交。创建恢复要求原scope可读CSRF的SHA仍匹配，不自动轮换scope。读取/恢复均不把依赖故障当空车。

当前422统一通用失败，因为不能将缺价/目录不可用错误都展示为库存不足。`CartAddResult`保留原形状，成功返回精确字符串数量，原商品按钮仍负责原路径跳转。浏览器缺Web Locks/SubtleCrypto或显式关闭时不暴露写适配器。
