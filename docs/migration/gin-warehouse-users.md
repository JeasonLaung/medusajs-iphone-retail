# 新仓库用户管理

React Admin `/warehouse-users` 使用 Ant Design Table、Drawer、Form、Input.Password、Switch、Radio、Transfer、Checkbox 和反馈组件。全仓与指定仓库明确分开，指定列表为空即没有仓库访问权。穿梭框支持搜索并同时展示可选与已选仓库；被删除仓库的既有绑定保留标识，可移除，不静默遗失。

Gin GET/POST `/api/admin/warehouse-users` 使用现有私有响应、管理会话、Origin、CSRF 和请求体限制。查看同时要求 `authorization.read` / `warehouse.read`，写入还需 `authorization.write` / `warehouse.write`。只管理本生命周期创建的新 warehouse 主体，不把员工、旧用户、客户或供应商转换成仓库账号。用户名不作为身份，邮箱新建后固定；同邮箱不能认领历史账号或业务关系。

0054 增加默认关闭的能力标记、新账号/专属角色归属与不可变变更收据。还需显式开启0053范围能力，生产不会自动开放。账号、专属角色、warehouse主体、范围及绑定、动作、审计前后快照、全局权限版本和收据在一个事务完成。最多100个角色的现有授权目录上限保留；每个仓库账号拥有独立角色。不改已有权限模型动作词汇。

管理员只可选择自身持有的 `inventory.read`、`inventory.stock.write`、`order.fulfillment.read`；写入和成功重放都重新检查当前管理权限与所请求动作。不能借此授予全店订单、付款、金额或商品读取。仓库账号登录使用已有新系统管理会话，但全店权限快照仍为空，全店接口仍拒绝；范围库存与配货页面后续接专用接口，不在这里放宽全店接口。

创建必须提供12至72字节密码，bcrypt哈希后写入新账号；编辑留空保留，非空重置。密码不回填、不返回、不进入JSON请求记录或前后审计；收据单独保存单向密码验证哈希以绑定同一次提交的完整输入，原密码不落审计。前端仅在打开的提交状态内保留本次输入供丢响应重试，关闭/成功清空，不写本地存储。页面只显示安全通用错误。

所有编辑递增身份代数，覆盖启停、范围/动作修改和密码重置。旧Redis会话即使仍存在，也会被现有数据库身份检查拒绝；重新启用不会使旧会话复活。对缺失或删除仓库，启用的用户不能绑定；关闭用户允许保留软删除仓库以便及时停用，重新启用前必须清理绑定。空范围是合法的无仓库权限状态。

操作使用UUID和权限目录版本；并发同操作只产生一个账号，响应丢失重试原ID、版本及内容。密码不同的重试拒绝。版本冲突/重复邮箱提示关闭刷新；结果未知时锁住表单，可显式重试原提交。变更末尾收据故障整体回滚，不留下可登录但未绑定的账号。全局权限行先取得写锁，与范围校验的业务事务共享锁协调。
