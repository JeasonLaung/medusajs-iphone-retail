# 设备来源与自动建仓

新 React Admin 仓库页提供“设备来源”抽屉，Gin 私有 GET/POST `/api/admin/device-sources` 承接原 `workflows/device-source.ts`。保留来源 name/type、有效来源名称不能重复，以及创建时自动新建同名仓库、绑定默认销售渠道、绑定 `manual_manual` 配送服务的行为。自有与供应商基础来源均保留，不包含供应商门户或供量/代发操作。

原来源工作流取第一个 store 的默认渠道；新入口明确使用服务器配置 `STOREFRONT_STORE_ID` 指定的有效商店，要求有效且启用的默认销售渠道、有效且启用的手动配送服务。缺配置时事务拒绝，不建无关系的来源。请求不能指定任意已有仓库、渠道或 provider，入库位置将继续以来源绑定为准。仓库创建时无地址，沿用原行为，可在已有仓库编辑表单补充。

新增显式 `device.source.write` 动作，更新授权模型哈希及动作表约束；既有角色不自动加权。读要求 device.read + warehouse.read，创建还要求 device.source.write + warehouse.write；新账号当前权限在事务内先重查。warehouse/supplier 主体拒绝此全店入口。独立新账号 bootstrap 明确列举创建时动作，旧账号/角色不迁移。

先取设备事务锁，再锁仓库管理修订。设备 identity/commands 与仓库管理能力需开启，迁移默认仍关闭。来源、仓库、渠道关系、provider关系、两域修订及操作收据一次提交；末尾失败全部回滚。来源创建同步推进仓库管理修订，旧仓库编辑快照不能静默覆盖新增后的状态。名称按原精确文本判断重复，不做大小写合并。来源/仓库后续导入和修改须遵守一致锁顺序，直接绕过命令的任意 SQL 不在该并发保证内。

请求只接受规范 UUID v4、十进制64位修订、1—100字符规范名称和 self/supplier 类型；拒绝重复/未知/缺字段、null、非字符串、附加JSON、查询参数及超长正文。同操作同主体、同商店、同内容重放原结果；撤权先拒绝，再考虑旧收据。来源或仓库已删除则不能重放成功。目录最多1000条，超限失败而非静默截断；仓库已删除时保留来源历史并明确显示仓库不可用。投影不含供应账号、联系方式、成本、metadata或客户数据。

抽屉复用 Ant 表格、表单、输入与单选，使用原主题。丢响应保留原请求并锁住表单与重新读取按钮，只允许重试原保存；409/403等明确失败后要求重新读取。只读权限不展示创建动作。成功后刷新来源及原仓库表；入口不改变已有仓库编辑行为。

独立源码快照排除未提交的 Mollie 通知与其他业务修改。Go全包、56项迁移和三个真实SQL/HTTP套件通过，包含来源4请求并发仅创建一次、不可变重放、缺商店/渠道/provider拒绝、重复名、撤权后重放拒绝、仓库主体拒绝、末尾收据故障整笔回滚、删除仓库后重放拒绝及仓库修订推进。原库存和仓库用户用例继续回归。Admin类型检查/构建及原19项浏览器回归通过；专门合成API浏览器用例覆盖丢响应重试、只读、加载恢复和重复投影拒绝。

`python retail/scripts/test-warehouse-inventory-joint.py --device-sources` 运行真实浏览器→Vite→生产Gin→独占人工MySQL/Redis。新账号登录后分别创建自有和供应商来源，刷新确认来源/仓库、查Gin投影、重复名拒绝、中英文及390宽度通过。结束回查MySQL：来源/收据/默认渠道关系/provider关系各2，原精确库存仍为 `100.000000000000000001`，库存修改收据0。MySQL/Redis单核768/128MiB；仅API随机端口绑定127.0.0.1，桥接网络不限制外连，未验证TLS安全Cookie。按归属清理容器、网络和临时二进制后才保存联合报告。

证据见 [测试汇总](device-sources-report.json) 与 [真实联合](device-sources-joint-report.json)。来源具备实际后台入口，但设备入库、照片校验/文件迁移、仓库员工设备操作、订单分配/配货/发货及前台履约联合仍缺，C05/C07与整个前台保持未验收。没有操作部署服务器或真实业务数据。
