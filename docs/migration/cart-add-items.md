# 购物车加购事务与HTTP

2026-10-28。`0027_cart_item_operations.sql` 新增独立默认关闭的 `cart_item_runtime` 与持久操作回执；完整显式迁移计划为27。旧0025来源结构及0026匿名授权不改写，旧购物车/客户编号不授予本操作权限。没有执行生产或旧开发库迁移。

`cart.AddItem` 用同一MySQL REPEATABLE READ事务执行：当前cart/access和独立能力检查→配置店铺/渠道→锁定匿名归属与购物车→当前代数和未完成/未删/无客户绑定检查→同操作回执检查→预期版本→加载完整候选购物车→服务端目录/配置完整性→整车共享库存→按合并数量选价→写行/递增版本/保存来源price与price set标识和结果回执。行项目、版本、回执失败全部回滚。

同SKU重复加购合并原行ID，并按新数量重新选阶梯价。客户端不能传价格、税标记、折扣、仓库、库存模式、metadata或客户/店铺身份。目录复用现有published/店铺渠道与产品内选项成员检查，商品/变体/配送标记与名称快照由服务端加载；未知metadata不复制。自定义价格行、无SKU历史行或同SKU多条歧义行暂拒绝本增量命令，后续迁移不能借此删除历史。

精确价格进入raw；DECIMAL(38,18)兼容列由程序明确向零截断至18小数，读取仍严格raw优先，不依赖MySQL隐式舍入；超过20整数位的有效价拒绝。保留sale的compare_at以及价格的显式含税标记，金额不经float。

回执按cart+UUIDv4键定位，绑定当前代数和完整命令hash。相同请求重放返回原操作版本/行ID/数量，不重复累加，即使购物车后来又发生变化；该回执不是当前详情，调用方应另行读取。相同键换请求409；不同操作竞争同一预期版本只有一方提交。每次重放先核对当前持久授权，旧Redis或历史操作键不能恢复已撤销归属。

`POST /api/store/carts/:id/line-items` 请求为 `{"version":"1","variant_id":"variant-id","quantity":"1"}`，UUIDv4置于Idempotency-Key。要求HttpOnly possession+CSRF及精确配置Origin；只接受JSON字符串字段，拒绝重复/null/数字数量/未知字段/尾随对象/查询参数。成功或重放均200，返回cart_id/version/line_id/quantity/replayed；不续cookie。错误400/401/403/404/409/413/415/422/429/503保留明确边界，全部private,no-store与请求编号。独立持有凭证限流128次/现有LoginWindow，Redis故障拒绝。

## 库存口径修正

查阅实际安装Medusa `prepare-confirm-inventory-input`、`confirm-inventory`、`reserve-inventory` 后，整车规划器和目录上限修正为**每个库存组件单仓覆盖，不同组件可来自不同仓库**。整条商品行强制同仓会错误拒绝旧逻辑可准备的组合商品，因此撤销前批假设。共享库存项仍跨行/跨SKU合计，不能用单行分别通过代替整车检查。250组独立穷举现按组件枚举，单组件不拆分。

保留安全差异：未知/软删库存层、持久冻结或实际预留合计不符时拒绝，backorder也不绕过。这不声称完全复制旧Medusa宽松backorder，也不证明已完成成单选仓；旧确认步骤可按候选仓检查，预留却取每库存组件的第一个位置。新订单仍须在锁内重算和原子预留，本加购没有预留、扣减或设备数量限制。
