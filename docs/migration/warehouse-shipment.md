# 仓库整包发货

2026-10-30：仓库专用路径 `/api/admin/warehouse/locations/:location_id/orders/:order_id/fulfillments/:fulfillment_id/shipment` 支持读取发货版本与提交整包发货。当前账号必须同时持有 `order.fulfillment.read` 和 `warehouse.shipment.write`，并绑定该仓库。新接口不允许取消包裹，也不授予全店订单/配货权限。

平台和仓库共享同一个发货事务与回执实现。仓库授权在业务锁之前检查，随后复核包裹当前仓库、订单、取消状态和设备位置；任何旧回执也须重新核对仓库权限、原分配仍属于此包裹及设备当前位置。事务保持原数量、全部设备 packed、身份归一化、SKU、来源、整包行数量、物流标签、设备事件、发货数量及站内通知校验。发货不再次扣减装包时已扣的库存。

React Admin 在授权仓库包裹详情中显示 Ant 表单，使用当前仓库专用发货版本，提交物流单号及可选链接。无发货权限的账号不显示表单。结果未知时禁用编辑并保留同一操作 UUID、版本和正文重试；成功后重新读取详情，已发货包裹禁用再次提交。请求使用现有 CSRF 及同源会话约定，不更改原店面样式。

## 验证

- 隔离 Gin/MySQL：真实 HTTP 版本投影不含内部字段；取消、旧版本、包裹移仓、权限移除拒绝。最终回执失败时回滚；四并发只有一次新发货、三次重放；库存不变。撤销仓库绑定、移动设备、移除分配关联或移除发货权限后，旧成功命令也拒绝重放。原平台取消/恢复库存、仓库发货后的后续售后测试继续通过。
- 真实 React Admin → Gin/MySQL/Redis：平台实际预占、装包、取消、重新装包后，管理员创建新仓库发货账号。390px 英文页面填写物流并提交；仅丢弃第一次真实成功 HTTP 响应，第二次重试正文完全相同，成功读取唯一发货回执。刷新后物流仍在、再次发货禁用；1440px 中文页面验证字段与禁用状态。之后只读仓库账号中英/390及1440详情不显示发货表单，原权限撤销联合也通过。
- MySQL 再核对唯一物流标签、两个设备及分配 shipped、发货数量和精确库存/预留没有重复扣减。全部 Go 测试、Admin TypeScript 及仓库读取页面中英/双宽度回归通过。自有测试资源均清理。

执行 `python retail/scripts/test-warehouse-inventory-joint.py --order-parcels`，可通过 `WAREHOUSE_JOINT_BACKEND` 指定隔离后端快照；设置 `ADMIN_TEST_NODE` 为 Node 22。见 [发货报告](warehouse-shipment-report.json) 和 [包裹联合报告](order-parcels-joint-report.json)。外部物流接口/真实运单购买没有被此测试调用；原业务是手动物流单。仓库配货与更换已分配设备仍待迁移，不能把整包发货通过视为完整仓库闭环完成。
