# 付款结果页提交唯一订单与恢复

2026-10-30，C06。原结果页已调用 [Gin私有完成接口](gin-checkout-completion-http.md)，只有服务器成单收据成功返回才显示已确认。已有Mollie `paid`事实本身仍不代表成单成功；授权、失败、需复核与成单失败保持原待确认/失败/错误流程。

`checkPaymentResult` 继续从HttpOnly拥有权恢复当前购物车、比较URL提示ID，再以当前CSRF调用付款核实和空意图完成接口。URL不能提供支付事实或订单身份。购物车已关闭时通过同一私有完成接口恢复收据；当前草稿读取和付款查询之间发生另一标签页成单时，也能从404竞态恢复。依赖故障、余额/库存/优惠冲突或不可解析响应均不显示成功，不发起第二次付款。

保留原Logo、CSS、布局、图标、状态文案和最多12次、5秒间隔的串行重试。确认页尚未迁移，因此成功正文暂改为“付款已确认，订单已生成。”，不再承诺跳转至不存在的页面；订单详情迁移后恢复原确认页导航。没有新增页面视觉设计或在浏览器保存付款事实。订单ID只来自当前凭证授权后的成单收据。

## 验证

122个前台单元测试通过，新增仅凭成单收据成功、仅授权不成单、库存/促销/依赖失败、已关闭购物车恢复、并发标签页竞态、错误购物车/已撤销凭证/缺CSRF等用例。Astro检查288文件零错误零警告，正式构建通过。

正式Astro与Chrome配合合成API，在中英文390/1440宽度验证原地址/配送与付款结果状态。模拟成单已提交但响应丢失，页面保持待确认，刷新后在草稿已404时通过同一完成接口取得原收据，并且没有再次请求付款核实。成单接口不可用时paid仍不显示成功。授权/失败/外部cart/稳定回跳回归、无横向溢出和浏览器JS异常；已查看中文手机成功截图。

浏览器证据 [astro-payment-result-report.json](astro-payment-result-report.json) 附参与源码哈希。浏览器使用合成API，不能作为真实渠道或实际数据库联合验收；真实Gin/MySQL/Redis成单与失败恢复另见 [SQL/HTTP报告](cart-order-snapshot-runtime-report.json)。尚缺首次付款按钮、客户订单归属/确认详情页、取消/过期后的恢复和重新付款、实际渠道配置/沙箱/webhook及真实发信。整个购物闭环尚未完成。
