# 商品选项管理

2026-10-31：React Admin 商品详情增加 Ant Design「管理选项」抽屉，可添加现有共享选项、选择共享值、创建商品专属选项、添加专属值，以及移除未被 SKU 使用的选项或值。保留原商品详情、SKU、图片、库存及价格交互。抽屉独立查询最新选项，保存后刷新详情与 SKU，支持中英文、键盘操作和 390px 布局。

规则核对原 Medusa Dashboard 的 ProductOptionsManageForm、ProductModuleService 的 updateProductOptionValuesOnProduct_ / validateOptionRemoval_ / removeProductOptionFromProduct_：共享定义只选择现有值；商品专属选项可新增值；活动 SKU 使用中的选项或值不能移除；解绑共享选项不会修改全局定义；仅孤立的商品专属选项会退役。当前页面不重命名已有选项或值，与原商品选项管理表单一致。独立的全局选项编辑不在这次增量范围内。

同时修正新建商品时初始选项的 `is_exclusive=true`，与原表单创建商品专属选项一致，避免将每个商品的新选项误登记为共享定义。此前仅在已清理的独立演练库执行过新建商品，未改写源库或主试运行库的选项身份。

Gin `GET/POST /api/admin/products/:id/options` 使用 0090 的独立默认关闭 `product.options` 能力及不可变 `catalog_option_edits` 回执。继续验证登录、Origin、CSRF 和当前 `product.read` / `product.write` 权限。请求绑定操作 UUID、商品、员工和完整负载；重复请求恢复同一结果，撤权后不能读取回执，关闭开关后仍可恢复既有回执。严格检查重复/未知 JSON 字段、完整字段、规范 UUID/版本、重复名称和值、归属及边界；最多 8 个选项、每组选值 100 个、总选值 500 个。共享目录及历史关系超过读取边界时明确不可用，不截断后保存。

以 READ COMMITTED 和商品行锁与 SKU 创建串行，重新核对使用情况、版本和所有值身份，禁止跨商品专属定义、改写共享定义以及删除 SKU 正在使用的值。保留现有关系 ID；解绑关系软删除后再绑定产生新关系 ID，保留历史。专属定义、值、商品关系和最终回执同事务写入，最终回执失败会全部回滚。移除商品的某个可用值不会改写其他商品或已有 SKU。

## 验证

使用完整 90 项迁移的独立本机 MySQL、受限用户、Redis 命名空间，以及独立 Gin/React/Astro 端口。没有 Docker、源库/主库升级、真实付款、退款或邮件。

- 真实 MySQL：4 个同操作并发只有一次新写入；专属定义创建正确；过期版本、跨商品重放/专属选项、共享值新增和共享名称改写拒绝；其他商品不变；活动 SKU 占用组/值不可移除；最终回执失败时所有定义和关系回滚；未使用值可解绑；孤立专属组退役、共享组保留；关闭开关恢复回执及撤权拒绝。
- 实际 Chrome：登录 React Admin，在抽屉添加共享组选值、创建专属组选值，保存后创建同组选项 SKU，刷新后验证占用删除禁用，移除未使用值；直接提交删除使用中选项的 API 请求返回 409；公开商品接口仍显示同一 SKU 和新选项，Astro 对应商品页 200；中英文与 390px 布局通过，浏览器脚本错误 0，无 API mock。
- 后端全包测试、Go vet、Admin TypeScript 检查通过。
