# 已付款订单的本地成单事务

2026-10-29，C06。`cart.CompletePaidOrder` 在单个 MySQL 事务中协调已验证付款证据、订单快照/编号、库存预留、实收账目、购物车完成、成单收据和通知任务。没有远端扣款调用。当前是内部默认关闭的能力，尚未接入前台提交及订单确认页。

先锁定当前购物车拥有权，再读取完成收据。完成后仍检查有效代际、店铺、渠道、匿名拥有权及原付款操作/输入版本；完成购物车不再作为草稿读取。匹配重试返回同一订单，库存/账目/邮件任务不会重复。修改命令、撤销凭证或不同代际不能通过旧收据获取订单。

首次成单复用冻结付款请求、加密 paid 观察、独占会话/集合及精确金额校验。订单与库存/实收全部成功后，写入逐行绑定的加密订单通知任务，再关闭购物车并递增版本、写收据。任意错误回滚整个本地事务；已保存的渠道 paid 证据仍保留，可在库存恢复后使用同一操作重试，不能再次发起付款。

尚未接入优惠预算/属性次数登记，因此存在真实促销关联或促销调整时明确拒绝成单，不能漏记使用次数。该限制需要在开放前台前补齐。通知行状态 pending 表示可靠入队，未启动发送 worker，也不代表邮件已送达。订单客户归属、前台提交与确认页、支付沙箱验收仍未完成。

## 验证

8 个并发完成请求只提交一张新订单，其他请求返回同一收据；验证丢响应后的重试、完成购物车关闭、错误版本/代际/已撤销权限拒绝、加密通知有效且不可换行解密。在收据插入时注入末尾错误，订单、库存、实收、编号、购物车版本与通知任务均回滚；库存不足拒绝，恢复后同一 paid 尝试可完成。原订单金额读取回归通过。

证据见 [运行报告](cart-order-snapshot-runtime-report.json) 的 `order_completion`，附参与源码哈希。该证据是本地事务验收，尚不等于全前台购物闭环验收。
