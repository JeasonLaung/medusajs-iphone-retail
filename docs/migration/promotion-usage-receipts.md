# 预算持久回执与历史释放

2026-10-29：0032新增内部promotion_usage_operations，主键(scope_id,operation_id)，保留请求SHA、pending/registered/reverted状态、精确计数delta JSON、结果、创建/登记/撤销时间。它没有促销配置级联外键，避免活动删除时抹掉登记证据；创建同名表会失败，不覆盖既有表。通用promotion写能力仍关闭，没有新增公共路由。新应用依旧要求完整32个显式迁移，不在启动时DDL。

## 登记与重放

`RegisterUsageOnce`仍参与调用方事务。scope必须是服务器已授权的checkout/order范围，operation为本次业务操作稳定UUID v4。识别scope/operation不构成权限；调用方必须在首次调用和重放前都重新验证权限，不能因存在回执放行历史订单。不同operation会再次占用额度，最终结账命令必须保证一个业务操作复用同一UUID。

先按promotion汇总正金额并排序、规范十进制，同样金额的不同动作排列或拆分得到相同请求SHA；币种和可信属性映射参与SHA，当前时间不参与，避免已提交操作稍后重试因活动到期而失效。属性只进入摘要，不以明文存入回执。利用唯一主键插入/锁定回执行，随后按原RegisterUsage锁序更新计数；写入实际修改的promotion+1、budget金额/次数、具体attribute usage行+次数，再将回执转为registered。回执与计数同事务提交；任何错误必须全部回滚。

相同键和相同SHA返回原结果，不再查活动资格；相同键不同SHA报冲突。已撤销的键不能重新登记。事务中pending是中间状态，调用方不得捕获错误后提交半成品；该阶段不拥有提交，也不是完整结账命令。

## 历史撤销

`RevertUsageOnce`只接受原回执身份，不重新接受金额/属性/当前活动配置。锁回执后读取原delta，按促销、原活动、原预算、具体属性行的稳定顺序取得当前用量，减掉原delta，再将回执原子转为reverted。同一键并发或稍后重复撤销只返回原已撤销状态，不再释放。只释放该操作实际登记的计数，即使promotion.limit后来变NULL也保留原计数释放事实。

活动起止、停用、软删、promotion改挂另一campaign、budget币种/类型/属性变更都不改变原目标ID。预算和促销软删除后仍能按保存ID减计数，属性耗尽时软删除保留历史。属性记录只保存ID与所属budget，不把私有属性值复制到回执或日志。多个操作共享同属性行时只扣本次次数，另一操作用量继续存在。

原行被物理删除、属性行已失效/换父budget、用量小于原delta或回执结构非法时明确失败，不能零封底掩盖漂移，也不能改扣当前配置中的新预算。历史释放依赖物理保留原计数行；回执没有授权重建丢失事实。调用方必须回滚并进入对账。原低层RevertUsage仍保留当前配置算法作为受限阶段，正式结账重试与历史释放应使用回执入口。
