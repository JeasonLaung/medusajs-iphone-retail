# 每行配送仓库与共享库存

2026-10-28：`inventory.ReadCartStockAtLocations`复用整车库存规划器，增加由服务器解析的每行可用发货仓库限制。每行必须显式提供列表；缺少/多余行、重复/非法仓库ID、单行超过1000仓库或总计超过10000条行仓库关系拒绝。空列表表示没有配送仓库，不能回退到全渠道。

仓库列表与有效渠道仓库取交集，不能凭传入仓库ID读取外渠道库存或扩大供货范围。跟踪库存商品沿用有效库存项、required_quantity精确小数、迁移冻结和实时预留合计核对；单个组件全部需求放在一个允许仓库，多个组件可分仓。所有行仍共用库存容量，包括分属不同配送分组的行，不能各自判有货后重复使用同一份库存。backorder不能绕过坏库存层或仓库范围，普通行优先获得有限库存。

非库存管理行也必须有至少一个有效渠道配送仓库；原无约束的`ReadCartStock`行为不变，加购不会因此要求预选配送。内部库存分配不序列化到公共结果。该函数只读观察，不锁定、预留、扣减或形成可支付承诺；调用者仍须从当前有效配送选项/provider解析每行仓库，不能直接信任浏览器列表。

验证包括限制到不同仓库成功、共享单仓容量不足拒绝、空/外渠道仓库拒绝、backorder与坏库存层、非库存管理行、输入范围和禁止输出越界分配。实际SQL用例复用正式迁移和人工库存数据，对库存/预留/冻结/关系做前后指纹核对，证据以`admin-auth-report.cart_shipping_stock`与实现SHA为准。Go单元不替代实库证据。

当前尚未从购物车选中的配送方法组装全车仓库限制；报价阶段没有因此自动获得库存验收。后续需将所选方法、非配送行、完整商品配置和当前持有者版本统一到完整事务，再处理共享预留、运费保存、税费促销及支付版本失效。没有新增HTTP或启用checkout，T032/T033未完成。
