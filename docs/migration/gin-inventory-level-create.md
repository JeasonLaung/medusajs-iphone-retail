# 新库存项添加仓库库存

在现有商品详情 → SKU → 库存明细 → 库存项中增加「添加仓库库存」。使用 Ant 表单选择当前有效仓库，输入非负初始库存量及在途量；已有库存层在选项中禁用，继续使用原修改库存入口。新建操作不改变商品状态、SKU规格、设备档案、订单预留或配送渠道。

原设备流程 `medusa-store/apps/backend/src/workflows/device-operations.ts` 明确允许设备追踪使用已有数量库存而不接管它。此次保持设备登记和数量库存独立，补齐新SKU库存项没有仓库库存层的缺口。数量库存并不保证仓库已有对应可配货设备，配货流程仍需核对实物。

## 数据和权限

- GET `/api/admin/products/:id/variants/:variant_id/inventory/:item_id/level-creation` 返回当前商品/SKU/库存项绑定、仓库列表、已有库存层标记、共享SKU数量、开关及摘要。
- POST `/api/admin/products/:id/variants/:variant_id/inventory/:item_id/levels` 接收规范 operation_id、expected_revision、location_id、stocked_quantity、incoming_quantity，全部字符串。金额式数量使用既有固定18位小数的精确校验，不接受浮点数、负数、重复/未知键、null、附加JSON或非法UTF-8。
- 需当前 product.read、inventory.read、inventory.stock.write、warehouse.read。仓库员工和供应商不能访问全店建仓入口；仓库员工继续使用已授权仓库的库存读取/修改页面。
- 0064 创建独立不可变收据，新增默认关闭的 inventory.create_level 能力；不对正式数据自动启用。提交迁移数量为63，不包含原未提交的支付通知迁移。

事务先核对并锁定当前授权，锁统一建层能力行和库存运行时标记，再验证商品/SKU/库存项及目标仓库。初始预留量为零；现货、在途、预留三个标量和raw镜像同事务落库。当前有效库存层不能重复创建；目标仓库存在孤立预留或迁移差异时拒绝建层，保留核对证据。软删库存层不被复活。

提交摘要包括当前绑定、库存项、有效仓库、库存层、预留、迁移差异及共享关系。成功收据绑定原账号、商品、SKU、库存项、仓库与完整请求；相同请求返回原层ID，不再次增库存。重放仍检查当前权限和目标关系。未知结果锁定原输入，只允许同请求重试；冲突/权限变更要求重新读取。

## 验证范围

隔离SQL验证真实新建SKU的库存项、初始默认关闭、同操作四并发唯一库存层/收据、重复仓库拒绝、精确raw数量、零预留、在途不计可售、公开可售判断与超卖拒绝、初始零量、过期配置、孤立预留及迁移差异拒绝、末尾收据失败回滚、权限撤销及已删/解绑对象重放拒绝。

真实浏览器联合从登录、新建SKU进入库存明细，添加仓库及精确数量，再从公开Gin商品API验证可售数量；沿用原修改库存减少现货，公开可售结果同步变化，刷新保留。中英/390px、已建仓禁用和无脚本异常随页面验证。后台另验丢响应同请求重试及当前权限变化。证据为 level-create-report.json、level-create-joint-report.json。
