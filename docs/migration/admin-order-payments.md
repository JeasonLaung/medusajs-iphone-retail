# 后台订单支付详情

2026-10-28。新增已认证私有 GET `/api/admin/orders/:id/payments`，React 订单详情使用 Ant Design Descriptions、Table、Tag、Alert 展示付款集合、支付会话、付款及可展开的扣款/退款记录。独立加载、错误和重试不会隐藏成交行与订单金额；请求取消、401 会话过期和订单版本变化处理沿用现有约定。付款展开/收起使用具备中英文可访问名称和 aria-expanded 状态的 Ant Button，支持键盘操作。中英文、390/768/1440px 继续验证。

查询在同一个只读 Repeatable Read 事务中核对订单与支付结构标记，读取当前有效订单、未软删除的关联集合和子记录；不按订单状态推导付款状态，也不根据 completed、captured_at 或合计授予操作权。缺少有效付款集合拒绝不完整响应，最多 100 个集合、全单 1,000 个会话、1,000 个付款、各 1,000 个扣款/退款，超界返回 503，不截断后假装完整。未知/重复查询参数一律 400，订单不存在/删除 404，依赖/结构/金额异常固定 503。

金额使用来源 raw 数值优先规则及 Go 精确十进制组件，以字符串传至前端；nullable 授权/实收/退款合计为 null 时显示破折号，保留未知与零的区别。付款和每条支付会话各保留原币种。退款保留原付款关联，不将退款 ID 当扣款 ID。不合并不同币种，不推算仍缺的汇总或可退款额。

响应字段使用显式 DTO/SQL 投影：不读取 provider data/context/metadata、客户主体、付款方式、退款备注/操作人、密文或解密密钥。前端验证精确字符串、数组上限、版本和关闭的操作标记，并将允许字段重新投影；数字形式金额与未知授权标记拒绝。

历史支付存在合法 hold 时显示“历史支付冻结”；缺少账本时显示“操作资格未核对”。显示 hold 不等于重验来源/目标哈希或远端对账。operations_enabled 固定 false，未新增扣款、退款、取消或 worker 入口，也没有恢复旧账号身份。

## 验证与剩余范围

人工 MySQL 验证当前订单与其他订单隔离、超出 JavaScript 安全整数且小数 18 位的金额、最后一位退款精度、SQL NULL 保留、未软删除扣款/支付可见、已删除关联隐藏、缺少集合/非法 raw/关闭结构/超出 1,000 条子记录拒绝、缺少 hold 不放行、敏感字段不进入 JSON，以及查询完整指纹不变。实际认证路由通过浏览器验证未知参数 400 和退出后 401。参见 [SQL 报告](admin-auth-report.json)、[真实浏览器报告](admin-live-report.json) 与 [UI 状态报告](admin-ui-report.json)。

固定来源的商品/库存/客户/订单/支付整合演练另核对每个订单的集合关系、付款及扣款/退款数量、明确字段与精确金额，保持全部业务表/回执/hold 指纹不变。缺少父项的订单单独返回不可用，不能当无支付。该固定来源已核对 13 个订单、13 笔付款、13 个会话及 10 条有效扣款；这些订单没有有效退款行，退款精度由人工场景验证，未把其他来源退款误关联到订单。详见 [真实整合报告](catalog-mysql-rehearsal-report.json)。

当前仅有新建 admin 身份的私有查询边界；完整逐角色/仓库/供应商授权、支付详情独立导航/查询、退款原因私有字段权限、provider 远端对账、新交易创建/扣款/退款事务、正式全域协调器和 Astro 尚待实现。T035/T036/T038 未整体验收。
