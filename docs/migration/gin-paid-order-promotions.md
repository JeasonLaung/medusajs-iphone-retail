# 成单优惠登记

2026-10-29，C06。本批把既有促销计算、预算登记和撤销日志接入 `cart.CompletePaidOrder` 的实际提交事务，取代上一批对所有促销订单的临时拒绝。未开放新的公网接口或改变原前台样式。

在当前凭证、冻结付款、加密 paid 事实、订单快照和库存预留通过后，内部方法读取同一事务的冻结购物车上下文与调整代码，锁定当前促销/规则/预算并重新计算。以目标行、促销ID、代码、精确金额和含税标记比较完整多重集合；促销关系也必须一致。不得只比较最终折扣总额，不得修改已付款购物车的价格或折扣。如果配置/规则、额度或折扣归属变化，整体成单拒绝，原 paid 证据保留。

登记金额使用服务端重新计算且与冻结调整完全一致的正数，不接受浏览器提供的价格、优惠金额、客户身份或预算属性。邮箱属性只能从当前私有购物车上下文读取，匿名购物车不伪造 customer_id。`RegisterUsageOnce` 以新订单和原付款操作为键，写入使用次数、预算/属性次数及精确撤销增量日志，与库存、实收、购物车关闭、通知和成单收据一起提交或回滚。完成收据重试先返回已有订单，不会再次校验已经耗尽的额度或重复消耗优惠。

没有优惠的购物车也经过该规则检查，保持原有成单路径。手工无促销调整不充当预算登记；所有重新算出的促销调整都必须能在冻结购物车逐条匹配。发起付款之前的优惠操作接口/页面尚待连接；当前是完整本地成单协调器的促销部分，不代表购物全流程已完成。

## 验证

独立源码目录运行完整 `go test ./...` 和 `python retail/scripts/test-admin-auth.py --order-snapshot-only`，真实隔离 MySQL/Redis，47 份正式迁移，不包含未提交的0037迁移。禁外网、无映射端口，容器分别单核/768MiB及单核/128MiB，结束按本次所有权清理。外部支付使用隔离适配器，没有真实扣款。

真实使用固定1.25 EUR商品优惠，付款渠道结算157.19 EUR。两个购物车在额度使用前均已冻结并取得 paid 事实；第一张通过4个并发重试只形成一个订单和一份使用记录/撤销日志；第二张因同一邮箱额度耗尽拒绝，订单/库存/实收均未泄漏。第一张在额度耗尽后仍可安全重放完成收据。改动促销配置或冻结调整的代码均拒绝成单。在成单收据插入处注入末尾失败，优惠登记与订单等全部回滚。成单过程中没有再次请求渠道创建付款。
