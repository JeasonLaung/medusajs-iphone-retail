## 数据与命令边界

`cartDisplay(view)` 按行 ID 合并上一批同快照保存展示和精确金额，保留服务端 created_at DESC/id ASC 顺序与已下架行；缺少、重复或额外展示行不当空车。行数量先核对 1—1e9 后才进入原数字输入控件；数量合计以 BigInt 显示。单价/行小计/摘要金额不经 Number，不用前台浮点乘法重造保存小计。货币按原 en-IE/zh-CN 规则格式化，支持超安全整数和负金额。

当前变体用于配置详情、专用链接、演示标记及库存提示，缺少变体继续显示原未知库存文案。Gin 权威 max_fulfillable_quantity 代替旧池化数字库存；超 1e9 的库存只在控件层限为命令上限，完整大整数不转浮点。冻结/不完整观察不授予可购买状态。没有将保存配置当实时库存或重新报价。

CartTemplate 接收显式 CartCommands，默认关闭；数量修改/删除仍由全车 busy 与各行 pending 管理。保留原输入失焦/回车、增加/减少、失败复位、原错误文案、移除等待态、移除后空车和键盘 focus 样式。生产命令协调器尚未接入，组件不直接发 API，不生成新的操作键或隐式重试。

checkoutHref 默认 null，展示原禁用状态且不生成结账链接。独立测试传入人工地址链接以对照原匿名空地址分支；它不是 Gin 能力开启，实际公开 checkout 继续 false。customer 布尔值只替代原组件的存在性判断，不恢复任何旧账号或历史归属。

## 独立浏览器对照

`legacy-cart.mjs` 读取原组件源码及 CSS，编译后的组件体不重写；仅桥接 Next 图片/国家上下文、测试命令边界、类型和匿名空地址的 checkoutStep。测试人工商品/库存与新 DTO 对应，不调用旧开发服务、旧数据库或真实账号。所有成功/失败命令由人工 `/test-cart` 响应控制，不把这套 UI 检查当作真实 Gin 购物车页面验收。

对照覆盖中英、390/768/1440，各宽初始两行、全车等待、修改成功、修改/移除失败、回车非法输入、库存上限、移除中、移除后空车，以及下架未知变体、缺货、演示价、空车和已登录的保存配送/折扣/税费摘要。每次核对文本及完整 cart-container 像素；另核对链接、控件禁用、页面无溢出、大金额精度与无水合异常。结果以 astro-runtime-report.cart_browser 与源码 SHA 为准，测试未通过时不据旧报告声称成功。

首轮发现新旧缺货 fixture 的库存上限不一致，修正为双方零库存后60组截图通过；测试收尾曾把故意注入的500资源日志当页面异常，现仅按精确 `/test-cart` 地址与500状态识别预期日志，页面异常及其他 console error 仍失败。未修改截图容差、原提示文案或删除失败断言。

最终联合回归通过：84对购物车完整区域截图逐像素相同、各状态文本相同，回车输入/库存上限/全车等待/失败与移除后空车行为通过，零水合异常；原40对展示区和24对操作区比较保留。43项单元、类型/build及完整零漏洞审计通过，原3项真实浏览器与Astro购买按钮两宽/SQL回查通过。本批购物车组件的成功/失败命令仍是明确人工边界，没有宣称组件已联调Gin。自有容器、网络、二进制及浏览器资源已清理，原开发服务四处完整响应200、旧stderr无新增。
