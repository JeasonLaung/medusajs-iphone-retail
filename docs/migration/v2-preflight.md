# v2 离线预检与旧 v1 写入入口退役

旧 `cmd/import-medusa` 及 `internal/importer.ImportCatalog` 已关闭。命令在读取文件、加载 dotenv、连接 MySQL 前固定以失败退出；库函数也只返回 `ErrLegacyDisabled`。删除了旧实现中静默忽略解析错误、生成缺省时间、仅保留部分字段及无法证明 SQL NULL 来源的路径。其历史代码可在 Git 中追溯，没有兼容开关可重新启用。

新增 `cmd/check-snapshot`，只读取显式提供的本地普通文件；不加载环境配置，不连接源数据库、目标数据库、Redis或provider。命令要求外部核定的完整文件摘要，不自动把当前文件的散列当成已审查来源：

```powershell
cd retail/backend
go run ./cmd/check-snapshot --snapshot ../../logs/gin-migration/source-v2-20261027-payment-rows.ndjson --sha256 b58a26812eeea8e75c6bd3e4ec4635b6260d8e704bc9a63fd095f0e7d9f13985
```

首先验证完整159表流并检查全部字段/raw配对/源CHECK，普通行实际调用严格转换；随后从同一文件句柄重新验证完整流及关系。两次均核对相同摘要，读取期间变化不产生可用报告。保护资料和历史处置行只统计，绝不把诊断当成专用解密、历史归属或导入许可。

编译后的可执行程序退出码：

| 退出码 | 含义 |
| --- | --- |
| 0 | 文件及当前普通值/引用检查通过；仍不接受完整导入或任何写操作 |
| 1 | 参数、文件、完整流/摘要、读取或资源上限错误；stdout 不输出部分JSON |
| 2 | 完整诊断已输出，但存在无效普通值或未解决引用 |

`go run` 可能把子进程非零状态包装为自己的失败状态；自动化需要精确退出码时，应先 `go build` 后运行可执行文件。

输出只包含数量、固定schema名称及输入文件摘要，`writes_enabled` 与 `complete_import_accepted` 始终为 false。保护行数与历史处置行数可重叠，不相加当作不同主体。默认最多100,000行、64MiB引用键载荷；后者不等同Go总堆内存限制。每条记录仍受既有16MiB上限约束。参数可下调，超限时整个报告无效。

[真实命令证据](v2-preflight-report.json)核对159表、27,140行、220,235字段、73,405 SQL NULL；普通可转换27,090行、保护48行、历史处置45行、无效普通行0。全部375项已知引用缺口保留失败，进程返回2。故意无效MySQL DSN不影响离线检查；旧命令携带不存在的文件仍先拒绝。错误摘要、行数及引用键上限拒绝且stdout为空；人工测试另验证截断尾部、两次读取之间的内容变化/seek失败不返回部分报告，私有内容不进入诊断输出。

`retail/scripts/audit-v2-preflight.py`可复现实证，编译物在Git忽略目录使用唯一名称，结束删除。新的正式v2全域写入协调器、运行/恢复账本、正式schema和领域验收尚未完成；本次退役没有用只读命令冒充已经可用的新导入器。T018继续未完成。
