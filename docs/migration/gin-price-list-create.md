# 价目表创建及初始价格

来源是已安装 Medusa dashboard 的 `price-list-create-form`：详情→商品→价格三步，默认 active/sale，必填标题/说明，UTC 时间可空，至少选择一个商品，可同时提交多个 SKU 的币种/地区/数量初始价格，以及可选 `customer.groups.id` 条件。来源价格字段可空，选择商品后允许没有实际价格；本实现保留该行为，同时提供完整初始价格录入，不以空表创建替代原向导。

新增 `GET /api/admin/price-list-creation?product_id=...` 和 `POST /api/admin/price-lists`。读取既有商品搜索/分页，选择最多20商品/合计500SKU，上下文保留价格集合及共享SKU提示、币种和地区。数量与金额复用原精确字符串规则，不经浮点；请求限制200条价格/100个客户组ID，超过限制拒绝，不截断。所选商品、SKU、集合和现有价格/规则变动均进入预期版本。

创建复用默认关闭的价格门禁、全局价格锁和0099收据表，无新DDL。私有会话、Origin/CSRF、product.read、price.read/write共同校验。单事务创建价目表、可选客户组规则、初始价格、地区规则及需要的新价格集合/关系，最后增加版本并写动作绑定的单条创建收据。基础金额/已有成员创建共用同一写入函数，保留原单条事务。相同共享价格集合的同币种/地区/数量条件重复输入拒绝且整批回滚；不同条件及来源重叠数量区间保留。

未知结果保留完整命令并锁定输入，只能以原 UUID 重试。当前权限/门禁、所选商品/SKU及生成价目表仍须有效；改变请求、跨动作UUID、已删表和撤权不能通过收据绕过。创建后列表和详情可见，原设置、整表删除及SKU成员录入沿用。

客户组条件目前按ID录入并原样保存，仅由可信 pricing.Context 的 CustomerGroups 匹配；匿名报价不匹配、公开查询参数不能伪造客户组。来源客户组名称选择器、当前新账号成员管理及登录购物链可信组上下文仍是待办；本批不迁移旧账号或令新账号继承历史组关系。

[原生数据库与浏览器联合报告](price-list-create-native-report.json)对应冻结 `cf7f8f9c99d5` 已通过，873份后端、127份Admin、593份Astro与工作区/快照逐份SHA匹配，二进制和日志核对通过。真实MySQL验证默认关闭、所选商品变化使旧版本失效、收据末尾故障整批回滚（包括新集合/关系）、六并发唯一表/收据、两个商品三条精确价格、共享SKU数量边界、共享集合重复条件整批回滚、改变请求/撤权/关门禁/删表重放拒绝，以及客户组规则在匿名上下文不匹配、可信组上下文匹配。

实际Ant英文桌面→手机三步向导跨搜索选择两个商品，填写地区普通价25、数量2–3价15.50、另一个SKU价21.25，首次真实成功响应丢失后锁定输入并以原命令恢复。SQL核对唯一创建收据、三条精确scalar/raw金额、数量镜像/NULL及地区规则。现有带渠道条件的价目表仍优先报价37.25；通过实际Ant补齐测试表说明并置草稿，SQL确认单收据后，新表在数量1/2/3/4分别报价25/15.5/15.5/25，第二商品SKU报价21.25。实际构建Astro中英×1440/390初始HTML与hydration后显示25.00，保留原100价格和零库存禁购，无横向溢出。创建Origin/CSRF/匿名写入拒绝，浏览器异常0。
