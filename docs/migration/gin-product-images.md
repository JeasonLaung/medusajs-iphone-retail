# 商品图片管理与上传

2026-10-31：React Admin 商品详情增加 Ant Design 图片管理抽屉，支持已有图片排序、图片地址添加、商品缩略图选择/清空、本地 JPEG/PNG/WebP 上传及未被 SKU 使用图片的移除。保留现有详情、SKU、价格及库存界面；旧版运行中 API 没有新能力端点时不显示新入口。

Gin `GET/POST /api/admin/products/:id/images` 沿用当前员工认证、Origin/CSRF 和 `product.read` / `product.write` 权限。显式迁移 `0089_catalog_product_images.sql` 增加默认关闭的 `product.images` 命令能力、公开商品图片内容表和不可变操作回执表；目录通用写入仍关闭。主试运行库未升级到 0089。

上传上限 3 MiB，服务端实际解码 JPEG/PNG/WebP、检查 MIME、像素范围与规范 base64。上传内容与图片记录、图片排序/删除、商品缩略图和操作回执在同一 MySQL 事务保存；失败不会留下孤立文件。图片内容采用已有原生照片功能的数据库持久化方式，但使用独立公开商品图片表，绝不读取设备/回收私有照片。

创建 UUID 绑定当前员工、商品及完整请求 SHA256。相同操作并发只执行一次；过期版本、变更重放、外商品图片 ID 及现有图片 URL 替换均拒绝。每次重放仍检查当前权限；关闭创建开关后允许恢复已成功操作回执。事务采用 READ COMMITTED 和当前商品行锁，避免等待并发写入后读取旧快照。排序/新增不改变原图片身份和关联，独立于图库的已有商品缩略图可以保留。

被活动 SKU 的图片关联或缩略图使用的图片不能静默删除，UI 明确显示原因并禁用移除。后续已补齐 [SKU 图片关联写入](gin-variant-images.md)，可显式解除关联及清空/更换缩略图；商品图库不会自动解除或重写原有关联。

`GET /api/store/catalog-images/:image_id` 只读取仍附着在未删除商品/图片上的商品图片内容，校验 SHA256 后返回准确 MIME、nosniff、限制性 CSP 和 no-store。商品图片与原 Medusa 商品文件一致是公开资源，包括草稿商品的上传图；不作为私有文件存储。Astro 提供同路径公开图片桥接，仅使用服务器配置的 Gin origin、固定图片路径和无凭据请求，不跟随重定向、不转发浏览器 cookies，读取限 3 MiB。图片移除后公开接口返回 404，原内容记录保留用于审计。

## 验证证据

专用受限 MySQL 用户、独立数据库、独立 Redis 命名空间和独立 API/Admin/Astro 端口运行完整 89 项迁移。公开目录依赖从完整校验快照导入，没有修改源库或主试运行库，没有调用支付或邮件。

- 真实 MySQL：默认关闭、4 个并发上传只生成一份、变更重放/过期版本拒绝、最终回执失败时完整回滚、原缩略图保留、SKU 关联与仅 SKU 缩略图使用均阻止删除、移除/清空后图片不可读、关闭开关恢复回执以及撤权后拒绝。
- 真实 React Admin → Gin → MySQL/Redis：文件上传、原文件 SHA256/MIME 核对、地址添加、排序、缩略图、移除、刷新、中英文及 390px 移动布局通过。
- 真实 Astro → Gin：公开桥接返回与原文件相同字节，正式商品页图库实际解码到预期尺寸，没有模拟 API，浏览器脚本错误 0。测试期间出现一条 Ant CSS-in-JS 卸载清理提示，不影响检查结果。
- 前台 176 项测试通过，包含图片桥接凭据隔离、路径/MIME/重定向/大小拒绝；后端全包测试、JPEG/PNG/现有公开 WebP 解码测试、Admin/Astro 类型检查及相关 Go vet 通过。

详见 [原生图片验证报告](product-images-native-report.json)。主服务继续保持已验证版本，整体验收仍需已有商品选项管理、完整变体更新联动、条件价格和 C01—C11 剩余联合验证。
