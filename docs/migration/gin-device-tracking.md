# SKU 开启单台设备追踪

React Admin 商品详情的 SKU 表增加“设备追踪”入口与 Ant Drawer，Gin 私有 GET/POST `/api/admin/products/:id/variants/:variant_id/device-tracking` 承接原 enroll 操作。原商品、价格、库存入口保持原行为。此操作只开启追踪，不代表设备已经入库，更不替代数量库存或订单预留。

新增显式 `device.read`、`device.enroll` 权限和授权模型版本哈希；既有角色不自动获得权限。读取同时要求商品读取、库存读取、设备读取；写入还要求开启追踪权限。当前账号/权限在同一事务内、业务锁与成功收据重放之前重查。warehouse/supplier 主体不能使用该全店入口。独立新账号 bootstrap 仍明确列出其创建时的权限。

继承原 SKU 条件：有效商品与变体、管理库存、不允许超卖、仅一个有效库存项且 required_quantity 精确等于1，库存项不能被其他有效 SKU 共用。当前配置锁定读取，不能根据浏览器传来的布尔字段开启。全局设备锁串行化追踪操作；后续变体库存关联写入/导入须遵守一致锁顺序。现阶段没有开放此关联的写入入口。

请求为规范 UUID v4 operation_id 和64位十六进制 expected_revision，拒绝重复、未知、缺字段、null、附加 JSON、查询参数和超长正文。状态摘要包含 SKU 库存配置、关联、追踪事实及设备修订；读取后配置改变返回409。成功后追踪行、enroll事件、修订和不可变操作收据同事务提交。重复同请求恢复原结果，其他账号/商品/SKU/内容不得复用收据；权限撤销后旧收据同样拒绝。默认 identity/commands 开关仍关闭，只在独占人工验证库开启。

抽屉使用既有主题和中英文本，解释无效配置及共用库存项原因。丢响应时保留原 UUID/原请求重试，结果未确认前禁用重新读取；409/403等明确失败后要求重新读取。只读权限隐藏开启按钮，已开启状态不重复展示操作。接口返回错误 SKU 时拒绝显示。

验证在仅包含本次暂存改动的独立源码快照运行，排除未提交通知代码。Go全包、三套实际SQL/HTTP测试（AdminAuthentication、InventoryStockEdits、ProductInventory）、Admin类型检查与构建、原19项浏览器回归通过。新浏览器用例通过丢响应同请求恢复、只读、共用库存项、409恢复、加载失败、错误SKU投影、中英与390宽度；该组使用合成API，不能单独证明Gin联合。

真实联合运行入口：`python retail/scripts/test-warehouse-inventory-joint.py --device-tracking`，只在独占人工库准备新账号与SKU，由浏览器登录后在商品详情开启追踪，再刷新和直接读取Gin投影；完成后回查MySQL，要求追踪行、事件、收据各1，精确库存仍为 `100.000000000000000001` 且库存修改收据0。联合证据单独保存在 device-tracking-joint-report.json。MySQL/Redis单核768/128MiB，仅API随机端口绑定127.0.0.1，独占桥接网络不限制外连，不宣称TLS安全Cookie验证；按标签归属清理容器/网络/二进制。

本批仍缺设备来源管理、照片存储校验、入库命令/页面、设备分配、配货、发货、取消释放与前台订单履约联合。C05/C07和整个前台保持未验收。旧服务和实际业务数据不参与测试，部署服务器不操作。
