# 已有价目表混合批量价格管理

来源 `price-list-prices-edit-form.tsx` 与 `common/utils.ts` 的 `sortPrices/comparePrices` 会将创建、更新、删除放进同一 `useBatchPriceListPrices` 调用。更新保留价格ID和SKU身份，修改金额与数量条件；原有币种/地区列不因金额编辑而转换。目标以 `BatchPriceListPrices` 严格 `create/update/delete` 命令接通私有 HTTP 和现有 Ant 价目表列表的“批量编辑价格”入口。

命令绑定原操作UUID、整表与所选商品/SKU/集合预期版本，沿用product.read、price.read/write、当前员工校验、默认关闭价格门禁和全局价格锁。最多20商品/500SKU/200个变更，所有字段及嵌套行严格逐键、类型及重复键校验。现有成员必须属于当前表和指定当前商品/SKU/价格集合，基础价格或另一张表的价格不能以有效SKU冒用。原收据action=batch-prices，与已有创建/添加/删除表动作隔离。

事务先读取全部参与价格及原始金额/数量镜像/规则审计，再软删明确删除行及其有效规则、原ID更新金额和数量镜像、添加新行，最后递增配置版本并写一条0099收据。没有新DDL。删除保留原ID及历史，不物理删除，这延续此前单价格删除的保留策略，与来源物理删除存在已记录差异。更新保留币种、地区及其他原规则、价格集合、表设置和元数据，不重建价格ID。可以在同一批次删除后录入同条件替代价格，也可以交换两条价格的数量区间。

重复检查针对全部变更落地后的条件，不拒绝中间交换状态；只将本批新建或变更数量条件的价格纳入新增冲突判定，历史已存在重复条件不阻止单纯金额维护，也不被自动重写。规则身份按完整属性/操作符/值/优先级在Go中排序比较，避免依赖MySQL LONGTEXT排序前缀。任何一条非法或末尾收据失败，全部更新/软删/规则/新增/版本一起回滚。同UUID六并发只一次新写入；重试仍核对当前权限、门禁、表及商品/SKU/集合成员，不能由旧收据授予权限。
