# 新购物订单到仓库发货与客户查询联合验证

本批沿用购物、账户订单、React Admin 订单配货/装包及仓库包裹页面，没有修改业务界面或样式。新增 `CHECKOUT_FULFILLMENT=1` 运行模式，把原来分段测试的购物和履约接到同一笔新订单上。它是隔离联合验证，不代表全前台、真实支付渠道或真实邮件收件验收。

## 实际路径

四个新客户分别使用英文/中文与 390/1440 宽度，经实际 Astro 注册、验证、登录、商品加购、地址/配送、Mollie 托管付款结果和成单；每单金额为 EUR 158.75。付款和验证邮件外部边界沿用原隔离适配器，Gin 订单、付款捕获、显式账户归属均使用实际业务事务。

平台新员工从实际 React Admin 登录，为这笔新订单选择一台设备并装包；仓库账号由平台员工经真实账号管理页面新建，只有指定仓库和履约读取/仓库配货/仓库发货动作，没有全店订单权限。仓库员工解除已装包设备分配，原包裹取消并恢复库存；平台重新分配同一设备、再次装包，仓库员工登记运单发货。解除和发货都丢弃第一次实际成功响应，再由原页面重试相同不可变命令，检查无重复副作用。

客户清除购物车凭证后，通过本人账户订单详情读取该笔订单：只显示有效发货包裹、实际运单与安全承运商链接，原发货进度和售后设备选择区读取实际已发货 SN；站内物流通知只属于该客户，标记已读持久化。退出及切换其他账号后，订单越权读取仍拒绝。

## 数据与证据边界

准备数据仅存在于脚本新建、带所有权标签的一次性 MySQL/Redis。测试只预设商品/库存/设备和新平台员工权限；不预造购物订单、付款捕获、分配、包裹或物流通知。原购物测试 SKU 使用 2.5 库存单位来验证小数库存；本模式在购物前显式改为序列化设备要求的每 SKU 1 库存单位，并在测试结束恢复。它同时在购物前选择已实现的 `manual_manual` 配送提供方，不改已成单配送快照，不冒充承运商预约接口。

后置 SQL 核对四个新订单各自的唯一成单/实收/邮件任务/预留操作、一个取消包裹和一个已发货包裹、一个取消分配和一个实际已发货分配、履约/发货数量各 1、订单数量预留消耗、一个本人已读物流通知，以及每单唯一发货命令收据。全局库存保留原有预留，四单净扣 4 个库存单位，新增订单最终预留增量为 0。随后继续原购物、付款恢复和邮件处理 SQL 回归。

运行：

```sh
CHECKOUT_PRODUCT_BROWSE=1 CHECKOUT_FRESH_CART=1 CHECKOUT_ACCOUNTS=1 \
CHECKOUT_FULFILLMENT=1 STOREFRONT_TEST_NODE=/opt/homebrew/bin/node \
ADMIN_TEST_BROWSER='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' \
python3 retail/scripts/test-customer-orders-live.py --checkout
```

模式只延长本次隔离测试的有界期限，不调整生产超时、权限或速率限制。报告写入 `shopping-fulfillment-joint-report.json`，包含实际浏览器/SQL 结果、相关源码 SHA-256 和资源清理状态；既有单纯购物模式保留独立报告。

## 本批验证结果（2026-10-31）

`CHECKOUT_FULFILLMENT=1` 联合验证及完整 `TestOwnedCartRuntime` 后续 SQL 回归退出 0；四单、四组解除/发货丢响应原命令重试、本人 SN/物流/通知和精确库存断言全部通过，浏览器错误 0。Go 全量测试及 vet 通过。报告见 [shopping-fulfillment-joint-report.json](shopping-fulfillment-joint-report.json)。

POSIX 脚本现在为本次浏览器建立独立进程组；异常退出时也清理专属 Astro 子进程，避免遗留监听影响下一轮。另用真实一次性父子进程/随机本机监听验证了异常父进程退出后子进程和端口均清除。清理不涉及既有开发服务。

付款成功后页面可能立即跳转，浏览器调试协议会丢失旧页的响应体。本批测试先读取实际 `payment-status` 响应，再原样转发其内容和响应头，避免把测试读取竞态误判为业务失败；没有替换 Gin/Astro 的业务结果。

最终同一版源码的履约模式 SQL 套件耗时 77.28 秒，原新账号购物模式回归 37.83 秒，均退出 0、浏览器错误 0、资源清理完成。原模式的最终预留增量仍为 10，履约模式为 0；两份报告保持独立。原模式证据见 [shopping-account-joint-report.json](shopping-account-joint-report.json)。
