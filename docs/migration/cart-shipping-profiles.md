# 购物车当前配送分组

2026-10-28：`cart.ReadShippingGroups`参与调用方的事务，先锁定当前购物车持有关系、店铺、渠道和版本，再通过有效行的当前变体、当前商品、有效配送分组解析分组。不使用保存的`product_id`或浏览器提供的分组作为关系依据。每行保留原ID、变体ID及十进制字符串数量；分组和行有稳定排序。

保存的`requires_shipping=false`行不参与配送分组，软删除行也排除。需要配送但没有当前变体、商品不可售、缺少分组、分组删除或同一商品出现多个有效分组时返回不可用。这个完整覆盖检查比原单个profile过滤函数更严格：原函数只筛出匹配行，会忽略没有profile的行；新协调器不能借此宣称整车已覆盖。仍保留非配送行原有行为，不在此重写保存的配送标记。

当前目录及关系使用共享锁读；GORM查询基准在设置锁后创建Session，避免多次目录关系查询相互污染SQL条件。函数不写行、不更新版本、不预留库存、不独立提交。调用方仍需在完整命令内处理幂等、版本更新和后续失败的整笔回滚。

`node retail/scripts/capture-shipping-profile-filter.cjs --check`离线执行实际安装的原profile过滤函数，固定6组人工输入、输出和来源SHA，证明关系取自`variant.product.shipping_profile`及不修改输入；不启动原应用。人工SQL验证范围见`admin-auth-report.cart_shipping_profiles`和对应实现SHA，包含手工配送行、缺失/删除/歧义、多分组、保存商品ID过期、当前版本和持有代数、数量顺序、非配送行以及只读指纹。只有报告实际包含该项且SHA一致时才构成通过证据。
