# 订单普通行的原子导入与缺失引用记录

2026-10-28。`orderimport.Import` 与 0017 承接 [0016 订单结构](order-schema-migration.md)
中的 28 张普通表、378 个字段。剩余 customer 的 12 字段含受保护 metadata，明确不从
本入口导入；这不是订单全域或客户主体迁移验收，也不恢复任何登录账号。

## 同一事务中的行为

调用方传入独立目标库的 `*sql.Tx`、已完整验证的快照 SHA 和 28 个表名对应的行集合。
空表也需明确提供；总量超过 100000 行、未知表、缺字段、非法类型、重复完整主键或
不符合 raw_* 配对的行均拒绝。输入表名不能变成 SQL 标识符，实际标识符来自编译计划。
调用方必须验证完整源流、来源 schema、全部数量和关系，不得仅凭局部 Import 成功提交。

预先完成所有严格转换；按固定物理依赖顺序、表内完整主键顺序写入。order schema
marker 以 FOR UPDATE 串行化导入批次，核对版本/模型/只读状态；不能与旧 worker 或
业务写命令共用迁移目标。组件不提交事务，不发送通知或调用支付/物流 provider。
调用方在任何错误、后续领域失败或验证不通过时必须回滚整个事务。

对新插入的 order_line_item.totals_id 与 return_reason.parent_return_reason_id 暂写
SQL NULL，在全部相关行存在后填回原值，最后逐字段锁定读回比对。全过程 FK 保持开启。
循环关系只在未提交事务内暂时断开，不会把 NULL 当作最终值；重放时绝不更新已有目标。

`migration_order_rows` 同事务保存来源表、完整长度编码主键及 SHA、快照 SHA、来源行 SHA、
完整转换后目标 SHA、首次随机尝试和策略版本。复合主键保留全部部分，不能仅凭 link.id
识别来源。相同输入重放需核对完整证据和所有目标字段；换快照、改源行、目标改变或
哈希碰撞对应不同完整主键均拒绝。DECIMAL 比对显式 CAST(38,18)，避免隐式 DOUBLE
吞掉末位差异。JSON null、SQL NULL、空字符串和 UTC 微秒时间独立保留。

## 引用差异

在本批行全部落定之后，对已审查的非空语义引用进行当前锁定读取：父表未正式接入记
`parent_domain_unavailable`，父表存在但原对象缺失记 `missing_parent`。软删对象仍是
历史事实，不凭 deleted_at 自动抹掉。不会补造订单、客户、付款、包裹或购物车。

`order_migration_reference_holds` 按来源完整主键与字段保存原父对象引用、原因、来源
与快照证据；released 受 CHECK 固定为 FALSE。这些是每字段差异，不是订单数量。
同事务创建与回放核对；本组件不解除、修复或删除 hold。父域接入之后仍需独立对账和
受审计处置，已有 hold 不会自动消失；若同一缺失引用的原因已变化，不能把旧证据覆盖
为新原因。`Result.ObservedMissingReferences` 是本次观察值，不是全部持久 hold 数量。

它们不全部等同于旧快照的 375 项孤儿：尚未导入的客户主体、尚未提供正式 schema 的
付款/履约/购物车也会产生阶段性的未解析依赖。原 375 项全域缺引用仍未修复。
后续业务读写必须结合对象归属、权限、领域状态与差异处理，不能据此自动取得历史订单。

既有循环边不被重放修复、客户普通入口拒绝与 hold 不能释放。没有使用真实账号。

目标、来源账本和差异账本。5 行受保护客户资料不导入，未连接旧数据库或部署服务器。
