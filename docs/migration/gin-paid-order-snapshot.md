# 核实付款后的订单快照

2026-10-29，C06 购物闭环的内部事务步骤，尚未接为前台成单接口。

## 已实现

`cart.StagePaidOrderSnapshot` 只接受调用方已有事务，重新检查当前匿名购物车凭证、版本、冻结付款尝试、独占支付集合和会话、币种及精确总额。只有已核实的 `paid` 且没有状态冲突才继续，`authorized` 不当作实收。付款核实事务将 `paid_observation_id` 绑定到对应的加密外部证据；快照步骤解密该行，检查请求摘要、同一购物车/尝试、不可变创建结果中的服务器保存支付ID，再用现有 Mollie 校验器核对币种、金额及远端状态。客户端状态字符串不能代替证据。

`orders.WriteCartSnapshot` 在同一事务内复制独立订单地址、商品/规格/图片/选项与原始价格、第一版本数量及零履约数量、配送方式/税行/优惠行、促销关联和订单购物车关系，生成新的订单行ID供后续预留使用；不把旧客户ID、邮箱对应历史主体或任意购物车metadata赋给新订单。商品行自身的既有业务快照metadata与原始JSON保留。新订单通过既有事务编号器获得整数展示号和19位业务号。配送金额来自已保存报价，`is_custom_amount=FALSE`。

订单金额接口原有计算体抽取为 `orders.ReadAmountSnapshot`，供后台读取与快照验证共同使用；后台返回结构及错误处理沿用。复制完成后使用订单读取逻辑核对购物车传入的每项精确总额，拒绝金额差异。订单自身多出的零履约统计不是购物车金额字段，不要求两边字段数相同。

`0047_order_checkout_codes.sql` 将订单四类税/优惠码从16字符扩为191字符，与购物车保持一致，防止有效长码丢失或成单失败；已有数据不改写。另为付款尝试新增外键绑定的证据ID，旧尝试默认NULL，需要重新核实付款获取证据，不能靠旧状态直接成单。

## 验证与实际边界

```powershell
python retail/scripts/test-admin-auth.py --order-snapshot-only
go test ./...
```

在独立源码目录验证46份正式迁移，不含工作区已有未提交0037通知迁移。真实隔离MySQL/Redis执行原后台订单读取回归及购物车/配送/首次付款/付款核实链路；外部支付使用隔离适配器。原后台回归覆盖版本过滤、raw价格优先与回退、精确金额、缺依赖拒绝和只读指纹。测试数据库禁网、未发布端口、单核限额，按随机所有权标签清理。

新快照用例覆盖实际158.75 EUR冻结购物车、地址独立复制、原始金额/选项JSON、配送快照、189字符中英优惠码、两种编号及新订单行映射；事务末尾主动回滚，核对全部相关表与编号计数未残留。配送版本写入注入失败同样整体回滚。未初始化编号、仅授权、需复核、无证据、错误摘要、篡改密文、错误凭证代次和普通数据库连接均拒绝。见 [实际运行报告](cart-order-snapshot-runtime-report.json)。测试没有完成渠道实收记账或库存预留，也没有对真实客户成单。

该步骤**不会自行提交、幂等成单、预留库存、登记促销预算、写实收/捕获记录、完成购物车、发送邮件或返回前台确认成功**。完整协调器必须先查成单收据，再在同一事务串联上述本地动作，任一后续失败都回滚快照与编号；外部渠道调用不得放入SQL事务。已付款但库存不足须保留可恢复状态，不能重建付款。前台发起按钮、唯一订单收据、私有订单查询和确认页仍未接通。

现有历史订单DDL对同一版本/配送方式只允许一条活动配送优惠，而购物车允许多条；本批未更改该历史约束。多配送优惠转换仍需按原实际规则核对并补齐，当前复制遇到该情况会拒绝并整体回滚，不能作为整站已验收。当前测试不证明所有促销组合、跨仓配货或真实支付沙箱完成。
