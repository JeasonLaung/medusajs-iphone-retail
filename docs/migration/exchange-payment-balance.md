# 正差额在线补款：订单金额前置校验

本页记录最初的内部金额校验与真实 SQL 回归。后续已新增[默认关闭的持久指令](gin-order-supplemental-payments.md)，但正差额在线补款仍未交付；顾客会话/HTTP、渠道发送/恢复、worker、实收及补款页面仍待。不能以本报告关闭 C07/C09 或整站迁移清单。

`orders.ReadSupplementalPaymentTx` 要求调用者持有 SQL 事务，并由调用者先完成新账号、当前会话、本店及原成单归属验证。它取得订单锁，校验期望版本、非取消/草稿/归档状态及未决订单变更，从当前原生金额减去精确交易流水计算完整正差额，再核对唯一活动未付集合、币种、精确原始金额及零授权/实收/退款状态。它拒绝集合已有活动 payment 的情况，但不代替付款协调器对历史指令、已删除付款及外部未决效果的恢复检查。

返回值只是私有 `{order, version, collection, amount, currency}` 快照，不授予顾客权限，不证明渠道已付。所有持久指令和首次发送都必须重新绑定并验证这份快照。读取过程不会改动购物车、集合、订单汇总、付款或库存。不会重新打开已完成购物车。

现有托管渠道按两位小数结算。当前差额不能精确表示成分时，本阶段拒绝发起，不通过四舍五入抹掉或增加订单欠款；完整付款流程还需明确支持的结算策略。本阶段没有修改原订单价格、税额或已有结算语义。

## 同步修复旧快照读取

MySQL 的 REPEATABLE READ 事务可能先建立普通读取快照，再等待订单锁。取得锁本身不会刷新该快照，后续普通金额/交易读取可能漏看另一事务刚提交的现金或商品金额。`CurrentPendingDifferenceTx` 现在要求真实事务，并对金额组成和交易使用当前共享锁定读取。查询会话克隆保留锁定条件，避免不同表的查询条件相互污染；原金额投影和精确 raw 优先规则继续复用。

回归先读取原总额 158.75 和一条原现金交易，另一连接提交人工 0.01 交易及商品税率变更；旧普通读取仍看到原快照。取得订单锁后，当前金额与交易同时可见，精确差额为 5.99。人工交易、税率和所有正差额换机事实仅存在于隔离测试资源，随后恢复/回滚；它们不冒充渠道成功证据。

这项修复同时作用于现有负差额退款额度及原生换机完成检查。

24 个拒绝场景覆盖集合金额/raw/币种、授权和部分实收状态、状态与现金矛盾、孤立 raw、完成/删除/缺失集合、已有付款、未决变更、取消/草稿/删除订单、零/负/不足一分差额、现金币种/未来版本/损坏 raw，以及多个未付集合。另核对旧版本拒绝、缓存汇总不能授予金额、raw 优先、显式零现金与 awaiting 可读取、最终仍只有原一笔付款与两个集合。
