# 显式 SQL 迁移执行器

2026-10-27。`cmd/migrate` 现调用独立 `internal/schema`，替换原来按分号切分文件、失败后整文件重试的草稿。此工具仍仅供独立目标显式执行，不在 API 启动运行，不构成完整领域 schema 验收。

`Load` 在打开数据库之前解析全部文件：四位唯一版本、固定文件名格式、文件/语句数与大小上限、完整引号/注释边界。文件按版本排序，摘要使用实际文件字节，换行改变同样属于变更。分号只有在非引号/非注释状态才划分语句；单引号/反引号和成对引号保持原样，注释里的分号不会变成 SQL。未闭合引号/注释、反斜线引用、双引号、执行注释、DELIMITER 和例程不支持时拒绝整个计划，不尝试不完整解析。它只支持当前受审查的 SQL 子集，不是通用 MySQL 客户端。

`Apply` 使用专用连接和全局命名锁 `eurorefurb_schema`，限时等待互斥。要求 autocommit=1，设置 UTC；完成或失败后通过独立清理 context 释放锁，无法确认释放时丢弃连接，避免把仍持锁会话放回池。它不依赖 Redis 锁，也不在错误中输出 SQL、驱动错误或数据库连接材料。

账本为已有 `schema_migrations` 加新增 `schema_migration_steps`，分别记录完成文件及逐语句状态。对所有已知记录先核对文件校验和、语句数和版本顺序；未知历史版本、已执行文件被修改、在已执行版本前插入遗漏文件、多个不可能的进行中版本均失败。旧执行器留下的完成文件仅有文件账本时仍兼容；这只承认历史执行记录，**不能证明目标表结构等于新设计**。

每条语句执行前先提交 inflight=true，再执行可能隐式提交的 MySQL DDL；成功确认后写 next_statement 和 inflight=false。已确认的前缀可在下次跳过。文件最终完成记录和步骤状态在一个短事务提交。重复执行不重新执行已完成的文件或已确认语句。

DDL执行失败、连接丢失，或 DDL 成功但进度写入未确认时，返回 `ErrUncertain`。再次运行继续拒绝，不猜测该语句是否已生效。必须先人工/后续专用工具检查实际 schema/数据与记录，确定这一条无效或已完成后，再明确对账。当前没有通用自动清理失败标志或回滚 DDL 的入口。成功执行过的 DDL 无法由 SQL 事务自动撤销，不能把这种情况称为整文件原子迁移。

人工 MySQL 8.4.11 测试使用既有单核、768MiB、禁网、无发布端口临时容器：

- 实际全部七个嵌入迁移文件在隔离空库执行，重复执行跳过七文件，两项账本均完成。
- 修改已应用文件、插入早于已应用版本的文件均被拒绝，不创建额外业务表。
- 第一条建表成功、第二条插入缺表失败时，记录一个已确认语句与一个不确定语句；直接重试拒绝。测试在私有人工库明确确认失败插入没有效果、补齐其依赖并显式对账状态后，执行器从下一条恢复，不重复第一条建表。
- 另一专用连接持有迁移锁时执行器拒绝；取消请求后可重新执行，完成后另一个连接能再次取得同一锁。
- 实际启动独立迁移子进程：先完成第一条建表，再让第二条ALTER等待父事务持有的元数据锁。父进程从MySQL PROCESSLIST确认该语句已到达服务器且正在等待，并读取next_statement=1/inflight=true后才终止子进程；不是用固定延迟猜测中断点。确认子进程以失败结束，释放阻塞事务，再次运行返回ErrUncertain，第一条表保留、后续第三条表没有创建、完成文件账本为空，不确定记录保持原样，命名锁可重新取得。服务器可能在客户端终止后完成或取消ALTER，两者都不能据此自动重放；测试故意不猜测这一竞态结果。

纯 Go 测试覆盖注释/引用分号、完整计划预检、重复版本、字节校验和及七文件解析。结果见 [mysql-type-fixture-report.json](mysql-type-fixture-report.json) 的 TestSchemaRunnerMySQL。顶层72项为71个SQL检查加一个Go套件；不是72个领域验收项。容器结束按所有权清理。
