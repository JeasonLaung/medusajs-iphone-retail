# 后台订单列表与成交快照查询

2026-10-28。独立 Gin 接口与 React Admin 首次提供订单基础查询，未接入 Medusa 运行时。
后台复用 Ant Design Form、Input、Select、Table、Descriptions、Tag、Alert、Spin 和反馈按钮；
保持现有主题、中英文及移动端布局。此范围没有统计图表，后续图表统一使用 ECharts。

GET `/api/admin/orders` 和 `/api/admin/orders/{id}` 经过现行新员工会话认证，
仅当前 admin 角色可访问。列表支持订单标识/显示编号/邮箱的字面搜索、六种订单状态、
创建时间升降序、稳定 ID 次排序及有界分页；未知、重复、空或非法参数返回 400。
只读 REPEATABLE READ 事务内查询模型标记、总数和当前页，过滤软删除订单。

详情选择 orders.version 对应的有效 order_items，读取历史 order_line_items 的名称、SKU、
成交含税标记，优先使用版本行单价、为空时回退成交快照单价。即使当前商品变体已经不存在，
仍保留历史成交描述。金额、数量及显示编号保持字符串精度，不经过 JavaScript Number。
履约、发货和退回数量分别保留；订单状态不推断支付或物流状态。
当前版本有有效订单行而成交快照缺失/软删时返回固定 503，避免把不完整详情呈现为完整订单；
详情超过 1000 行也拒绝截断。不存在/软删订单返回 404。响应明确投影，排除原 metadata、
地址、客户主体、原始 totals 和提供商 payload，错误不输出 SQL 或业务行。

页面以 URL 保存筛选和分页，进入详情及返回列表保留查询条件；支持加载、重试、空态、
缺失对象、会话失效及取消过期请求。详情显示当前版本成交行，退回数量可展开查看。
没有推算税额、折扣、运费、应付合计，也没有订单写命令。

验证证据：

- [实际人工 MySQL](admin-auth-report.json)：18 个迁移，当前版本选择、单价覆盖及 NULL 回退、
  超过 JS 安全整数的精确小数、字面通配符、分页、软删、模型漂移、私密字段隔离和读取指纹不变。
- [固定业务快照](catalog-mysql-rehearsal-report.json)：13 个有效订单和 14 条当前版本成交行，
  Gin 响应与独立 SQL 逐项核对；全域读取前后指纹相同。336 条普通订单数据及 5 个历史客户主体的
  导入/精确重放保持通过；293 条订单引用差异继续保留，全域原有 375 项引用缺口没有修复。
- [真实浏览器](admin-live-report.json)：独占人工 Gin/MySQL/Redis，订单导航、精确成交单价/SKU、
  字面搜索、非法 query 及退出后拒绝；中英文各 390/768/1440 三种宽度截图。
- [人工 HTTP UI 回归](admin-ui-report.json)：原账号、商品、价格及库存界面检查。

订单查询仅是基础切片。完整财务合计、支付/履约信息、订单变更/取消/退款/退换货、
订单与库存预留事务衔接、完整 RBAC/对象范围、全域正式导入协调器和 Astro 仍待完成。
不能据此宣布订单领域或整体迁移完成；未操作原开发业务数据或任何服务器。
