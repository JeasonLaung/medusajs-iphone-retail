# 付款成单后的订单邮件

`order_notification_outbox` 原已在唯一成单事务内保存加密通知。本次增加0049运行表、`ordermail.Store.Dispatch` 和独立 `go run ./cmd/send-order-mail [--once]`。必须显式设置 `ORDER_MAIL_ENABLED=true`；API启动、导入历史邮件或迁移数据库不会发送。PAYMENT密钥解密新订单通知/正文，MERCHANT密钥读取后台已批准的通知邮箱，均须持久保存。

订单邮件使用已批准、启用且未受历史导入隔离的最早邮箱；注册邮箱的专用选择不会自动套用于订单邮件。复用既有Resend传输，增加独立 `mail/op_{通知UUID}` 幂等编号及中英订单确认正文，包含订单编号和精确实付金额，不包含可绕过订单权限的链接。此正文为本期订单通知的基本实现，未声称已接原后台可编辑模板管理。

worker核对当前订单与加密通知的订单ID、邮箱、语言及本地成单/支付捕获记录，拒绝删除/取消订单、无实收、收件人变化。每次最多处理一封，全局订单worker SQL节流每秒一次。事务先保存加密的最终正文、发件配置指纹、首次尝试、计数与30秒租约，再提交并在事务外发送。超时8秒，无自动HTTP重试；网络/临时响应一分钟后最多总计3次，沿用同一正文及编号。进程中断后有效租约不重复发；过期租约可恢复。首次尝试超过23小时停止自动发送，避免模糊结果跨越幂等恢复时限。发件配置变化、损坏信封不使用明文或新发件人重试。发送成功只代表Resend接受，未证明收件箱最终投递。

工作日志仅含任务ID、状态和次数，无密钥、地址、正文或提供方原始错误。[后台订单邮件任务](gin-order-mail-admin.md)已增加失败查看及受限人工恢复；订单确认页面继续不显示“邮件已发送”。真实邮件收件与完整购物、配货、回收、售后通知仍待联合验收。

验证使用独立源码快照：48项迁移（排除工作区未提交0037），`go test ./...`通过。真实隔离MySQL/Redis的OrderRead/CartRuntime及新账户邮件回归通过。订单用例覆盖4个并发worker单次请求、事务提交后才发送、网络失败后正文与key不变、有效租约阻止重复与过期租约恢复、加密正文、已发送不重发、发件配置变化及密文损坏停止、23小时限制。Resend本身用拦截transport核对固定URL、幂等头和中英正文；没有真实外部发信。本次未改前台或现有开发服务。
