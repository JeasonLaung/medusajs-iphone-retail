# 商品基础信息编辑

2026-10-28。独立 React 后台使用 Ant Design Drawer、Form、Input、Select、Button、Alert；
图表仍统一 ECharts，本页没有图表。PATCH `/api/admin/products/{id}` 直接由 Gin 写 MySQL，
仅允许标题、副标题、纯文本描述和 draft/proposed/published/rejected 状态。
不修改 handle、选项、变体、价格、库存、元数据或来源迁移账本。

0011 显式迁移新增操作审计和命令能力表。通用目录写入仍关闭，仅启用
`product.edit_basics` v1；应用启动要求全部 11 个迁移与语句账本完成。
已有商品详情增加 64 位 revision，来自可编辑字段及微秒 updated_at 的明确投影。
每次编辑携带 expected_revision 与规范 UUID v4 operation_id。

事务内先以 SHARE 锁复核当前新员工账号、密码/角色/启用状态/撤权版本及命令能力，
再锁定未删除商品。不同版本返回 409；成功更新和 before/after/request 审计在同一事务提交，
审计失败整体回滚。同一操作的操作者、商品、请求内容必须完全一致，重试返回第一次结果；
当前读避免等待首次提交后读到旧快照。不同操作共用过期版本不会覆盖前一笔。
已删除商品返回 404；依赖失败返回固定 503，不回传 SQL 或请求数据。

HTTP 继续要求实际 Redis 员工会话、合法 Origin 和 CSRF。JSON 必须恰好六个明确字段，
拒绝重复/未知字段、尾随内容、非字符串、无效 UTF-8、孤立代理项和 NUL。
标题非空最多 500 字符，副标题 1000，描述 100000，HTTP 请求总上限仍为 1 MiB。
副标题和描述支持 NULL；界面不改动时保留原 NULL/空字符串，清空非空内容写 NULL。

抽屉保存成功后重新读取详情；失败保留内容。结果不确定时固定原请求及操作编号，
锁定输入，仅由用户明确重试；409 要求重新读取并核对，不能自动覆盖。
关闭抽屉会重新读取商品，401 回登录。标题、描述始终作为文本渲染。
