# 仓库履约独立写权限

2026-10-30：新增 `warehouse.allocation.write` 与 `warehouse.shipment.write`。它们属于专用仓库接口的权限词表；不授予平台订单读取、付款读取或全店配货能力。新 React Admin 的仓库用户编辑器和角色目录沿用 Ant 组件，提供中英标签，默认不勾选。`order.fulfillment.read` 保持只读。

`0082_warehouse_fulfillment_permissions.sql` 扩充 MySQL 权限约束和目录、更新权限模型摘要与版本，不修改任何已有角色的授权。权限模型有变化，须先执行显式数据库迁移再启用新代码；新代码拒绝旧模型。已有账号仍须由有权限的管理员明确授予所需动作。没有迁移旧登录账号。

实际 MySQL 升级测试先应用截至 0081 的旧计划，创建只读角色，再应用 0082；核实仅执行一条新迁移、只读角色授权原样保留、新模型就绪、未知权限 SQL 插入失败、迁移重放无新增执行。仓库检查还验证两个写权限分别在授权仓库生效，外仓拒绝；移除写权限后读取仍可用。

现有新建仓库账号 HTTP 集成测试增加：库存写权限不隐含履约写权限；管理员通过生产保存命令明确授予两个动作后生效，账号编辑撤销旧登录会话；重新登录仍不能调用全店订单；再次移除动作后两个写权限都拒绝。

隔离后端全部 Go 测试、后台 TypeScript、仓库用户中英及手机模拟接口浏览器回归通过。真实 React Admin → Gin/MySQL/Redis 原装包/取消/重新装包/发货 → 新建仓库账号读取联合也通过，新增写权限在新建表单默认未勾选。资源限制和清理沿用现有自有测试实例；旧开发数据库未执行迁移。

这是写操作的权限基础，尚未接入仓库配货、换设备或整包发货命令。不能把权限目录或检查通过解释为这些业务操作已完成，完整要求仍见 [写入契约](warehouse-fulfillment-write-contract.md)。
