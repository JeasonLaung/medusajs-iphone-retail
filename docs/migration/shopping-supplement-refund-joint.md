# 补款退款及替换品退货完成限制

本批修复独立退款 worker 对订单范围补款的漏选，并验证实际新购物订单的补款退款。替换品再次退货的完成限制继续保留，不能据此宣称第二次退货、C09 或 C01–C11 全部闭环。

## 修复及保留行为

原退款 `RunDue` 直接把 `scope_id` 当购物车 ID 关联店铺。原付款的范围是购物车，但补款使用订单范围，因此 HTTP 已接受的补款退款永远不会进入 worker。筛选改为订单 → 原 checkout 收据 → 购物车所属店铺；单笔 `Run` 仍按原路径核对当前权限、店铺、额度和受保护的完整付款证据，不从筛选结果取得发送权限。回归同时要求外店 worker 不选取，本店 worker 选取并保留丢响应恢复。

同一顾客实际完成原 158.75 EUR 付款、正差额换机、6.00 EUR 补款、替换出库，再提交第二次退货。员工扫码收回替换品、上传照片并检测，明确选择补款捕获，退款 6.00。付款及退款都由独立编译的实际生产 CLI 使用配置的 Mollie 适配器执行；外部渠道与邮件只使用本地隔离夹具。

来源 `medusa-store/apps/backend/src/workflows/update-after-sales.ts` 的完成校验要求申请设备的收回分配 `replacement_of` 为空。原生实现保留同一规则，所以这台曾作为替换品的设备无法完成后续退货。测试必须观察真实完成 POST 的 409 / `after_sales.unavailable`，第二次申请保持 processing，原换货仍 completed，且不产生第二条完成通知。共享退款测试默认仍严格要求普通原设备退货 Completed。

实际退货会写入商品行的 written-off 数量、冲减当前应付额。退款后实收累计 164.75、退款累计 6，净交易 158.75，当前订单金额 8.75，差额为 -150。原付款 158.75 没有被退款；保留来源每申请一次退款规则，不以本批冒充全额退清或差额归零。
