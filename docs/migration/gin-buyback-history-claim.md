# 人工核验后衔接历史回收

2026-10-30，用户确认允许后台人员人工核验客户身份后，将指定历史未完成申请绑定至重新注册且邮箱已验证的新账号。禁止仅按相同邮箱自动绑定；旧账号不迁移。

0081 新增 buyback_history_claims 保存申请、新账号、核验员工、核验说明与时间；唯一主键为申请，不提供改绑/删除接口。原申请 customer_id、联系方式、设备项和历史不改写。buyback_account_access 视图合并真实新申请回执与明确人工归属；原客户列表、详情、照片、客户动作、平台处理复用这份归属，历史查阅范围和离线快照证据继续独立保留。

POST /api/admin/buyback/:id/claim 复用管理员会话、Origin/CSRF、buyback.read/write 当前事务权限及回收写开关。严格解析 customer_id 与 10—1000 字核验说明，拒绝额外字段/重复键/null/超限；先锁新客户后锁申请，复核启用、邮箱已验证、明确店铺范围、未关闭状态。已付款/退回/取消、其他店铺、仓库身份拒绝。相同账号和说明重复提交读取当前状态；不同账号/说明拒绝覆盖。绑定及独立审计同事务，失败全部回滚。核验说明保存于受限归属表，普通审计只记录账号和申请标识。

Ant后台沿用详情抽屉，未闭单历史申请提供核验绑定表单。明确显示将开放原联系地址、图片和操作，要求操作人先核验；不设置默认客户，不按邮箱搜索或匹配。关闭申请没有绑定按钮，未获写权限也不显示。绑定后原客户前台页面和交互不变，使用新登录会话继续业务。

验证涵盖严格输入、已关闭/未验证/跨店铺/仓库拒绝、重复提交、拒绝改绑、原客户标识保留、原账号列表/私有图和客户继续操作、审计单条及审计故障回滚。真实浏览器沿后台表单绑定人工历史申请，客户通过原登录/详情执行操作并刷新持久。原完整回收交易、未绑定历史查阅以及真实历史快照/照片演练继续回归。真实人员身份核验、真实归属配置及正式导入尚未执行，不宣称线上接管完成。
