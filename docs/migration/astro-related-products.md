# 商品页推荐

继承来源 `medusa-store/apps/storefront/src/modules/products/components/related-products/index.tsx` 与 `rail.tsx`，补齐正式 Astro 商品页原有“探索更多 iPhone / Explore more iPhones”区。复用原文案、卡片布局、响应式宽度、横向分页、方向键与减少动态效果设置，以及项目现有 Medusa SVG 路径；背景及说明文字使用现有语义主题类。

## 数据和范围

公开商品列表新增 `related_to`，要求明确 `limit=50`、offset 0，不允许同时替换 handle、关键词、合集、分类或 SKU 选项筛选。Gin 在同一个只读事务内按当前可信店铺/渠道验证源商品，再读取其有效合集和有效标签；候选必须是当前渠道的已发布、未删除、非礼品卡商品。合集与“任意一个共享标签”取交集；没有合集或标签时不附加对应限制。客户端不能指定别的渠道。

沿用原 Medusa Product 模块 `getProductFindConfig_` 的默认 ID 升序。先获取最多 50 条候选，再在 Astro 排除当前商品，并仅当当前标题以 `iPhone` 单词开头时限制候选标题相同前缀，最后截取 12 条。没有候选时不显示推荐区，不补查后续页。推荐价格使用已有当前地区报价和精确金额格式化，保留有效 SKU 中的最低报价，不按库存隐藏整款商品。

主商品、推荐读取及渲染均不调用 Medusa 运行时。推荐依赖读取失败时省略推荐区，保留现有商品主体；没有伪造默认价格或推荐商品。本批不改变购物、库存、付款及评价操作。

## 验证

原生 MySQL 专项检查合集 AND 任一标签、空标签/空合集、有效标签、礼品卡/草稿/软删/外部渠道排除、私有源商品 404，以及 53 条符合条件记录仅返回前 50 条。

正式 Astro 独立构建浏览器检查 50 条候选的后置过滤与 12 条显示上限、当前商品排除、最低价、双语链接、横向滚动/方向键及原商品页选项、图库、评价、搜索等交互。边界单测额外检查前 40 条为非 iPhone 时只返回窗口内剩余 10 条，不向后补齐。

实际 Ant→Gin→MySQL/Redis→Astro 联合检查后台混合批量价格保存后的推荐卡片 €8.00，与商品 API 同价；初始 HTML 和 hydration 均包含推荐，当前商品不出现，中英文 × 1440/390 布局与禁购状态保持。最终冻结 a75b1de6767f 的 [真实联合报告](related-products-native-report.json) 已归档：881 后端、128 Admin 和 597 Astro 文件的工作区/冻结 SHA 逐份一致；Go 全包/相关 vet、201 项前台单测、独立构建/check 和正式页面 Chrome 回归通过，正常浏览器异常 0。自有数据库/socket/MySQL/Redis 键与临时服务清理通过，原开发服务七个入口均 200。

本地主 Gin 仍为原二进制、主库 86 迁移且写入门禁关闭；本批新查询和页面联合运行于专有测试实例。不能将本批证据当作主环境升级、合集真实数据联合或 C01–C11 全部完成。
