# 订单设备整包取消及发货

React Admin 既有履约展示中新增「包裹操作」抽屉，使用Ant Design表格、表单、单选、确认气泡和反馈。读取该包裹当前设备与状态；未发包裹可以整包取消，或录入原有物流单号/HTTP(S)查询链接后整包发货。保存后重新读取包裹、订单数量和履约证据；当前前台没有改版。

本批承接原 `workflows/device-operations.ts` 的 cancel_fulfillment / ship，以及已安装 `@medusajs/core-flows@2.21.2` 的 cancel-order-fulfillment / create-shipment 规则。不是调用Medusa运行时，也不通过仅改UI状态模拟出库。

## 权限与接口

GET/POST `/api/admin/orders/:id/fulfillments/:fulfillment_id/operations`。需要当前 `order.read`、`order.payment.read`、`device.read`、`order.allocation.write`、`order.fulfillment.read`，warehouse/supplier不能使用全店入口。仓库员工指定履约入口仍需单独接入本期业务，不以此全店入口代替。

0067新增默认关闭的独立包裹命令开关及不可变收据，已提交迁移累计66。新建预配/装包开关关闭时仍能显式启用现有包裹取消/发货；设备身份/命令及相关读取模型仍必须有效。本批不自动开启真实数据库的业务写入。

POST严格接收operation_id、expected_revision、action（ship/cancel）、tracking_number、tracking_url五个字段；拒绝重复/未知字段、null、额外JSON、过大输入和非法UUID/摘要。取消的两个物流字段必须为空；发货物流单号按原行为trim后1—200字符，查询链接可留空，否则必须HTTP(S)，拒绝控制字符与含用户名密码的链接。沿用Origin/CSRF与JSON类型检查。

响应投影保留可操作状态、成交行、SN和物流记录，不返回成本、内部库存标识、IMEI/EID或收货地址。收据审计记录内部精确库存/预留和成交行变化，页面无此权限外泄。

## 整包取消

订单必须当前有效，包裹未发、未送达、未取消；所关联的每个分配及设备均packed，同订单/来源且仍在包裹仓库。包裹明细、分配和当前成交行必须完整对应，不能只取消一部分设备或遗漏外订单分配。

按原生取消规则把该包裹的现货恢复到其实际仓库，并恢复订单预留：没有有效预留时，在包裹仓库创建新预留；已有唯一有效预留时，在其原仓库增加数量，保留原ID和位置。预留与库存层reserved数量不一致、多笔或绑定错误、历史差异、恢复后无法满足预留时拒绝并保留证据，不借取消修复库存。

同事务减少成交行fulfilled_quantity，scalar/raw同步。所有设备及分配退回reserved、清空分配fulfillment_id，并记录cancel_fulfillment事件；包裹保留canceled_at和原物品/历史关联。设备不会直接变成available。用户可继续预配解除，或再次装包；再次装包只扣恢复后的库存一次。当前不提供已装包时只释放某一台设备的复合命令，该源行为仍需后续接入。

## 整包发货

当前包裹设备必须全部packed、位置与SKU一致，身份按当前商品要求重新验证；全部成交行数量与分配计数精确一致。按包裹完整数量更新当前成交行shipped_quantity及raw，同时更新所有分配/设备为shipped、保存追踪单号、创建原生形态的fulfillment_labels和包裹shipped_at/marked_shipped_by，并留ship事件。

发货不再次修改数量库存或订单预留。原设备ship分支没有额外要求付款仍为completed，本批也不新增付款门槛；实收在预配与装包阶段验证。已发或已取消不能作为新操作重复执行；发货后的取消需走后续实际售后流程。

目前与装包一致支持manual_manual。其他配送提供商仍需真实订舱/标签/取消适配，不能悄悄切换手工提供商。本批录入的tracking只是原有物流信息记录，不声称已向外部承运商预约取件。

## 事务、重试及验证

锁顺序沿用当前权限→设备全局运行时→订单/包裹→库存运行时→明细；库存运行时排他锁与既有库存写入器的共享锁协调。摘要覆盖实际订单、包裹、物品、设备、成交行、标签及库存/预留。所有业务变更、事件与收据同一MySQL事务提交，末尾失败整体回滚。

收据绑定原账号、订单、包裹和完整请求。同请求重放返回原操作结果，不再恢复库存或增加发货数；重放前重查当前权限、订单/包裹和原设备分配/成交行存在性。取消后设备重新装到其他包裹，仍可回放原取消的历史结果。未知响应时页面固定原操作UUID、类型和物流输入，提供同操作重试；权限撤销后入口与接口均拒绝。

SQL覆盖取消/发货各四并发唯一执行、整包一致性、取消恢复新预留及跨仓剩余预留、取消后重装、精确数量、发货库存指纹不变、末尾收据失败回滚、已发重复/取消拒绝、物流记录、过期摘要、预留差异、当前权限与软删目标重放。后台27项浏览器回归包含两个新增用例：发货与取消丢响应时保持相同请求及权限更新，发货表单拒绝非HTTP(S)查询链接。

真实React/Gin/MySQL/Redis联合覆盖预配两台→装包一台→确认取消→两台重新装包→整包发货→刷新查询物流与设备、中英及390px；SQL核对包裹/收据/标签、精确现货、零剩余预留及成交行fulfilled/shipped数量。证据为 `order-parcels-report.json`、`order-parcels-joint-report.json`。
