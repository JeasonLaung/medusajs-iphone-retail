# 新购物订单的负差额换机结算

在原等价换机链路上增加独立 `CHECKOUT_EXCHANGE_REFUND=1` 验收模式，必须同时启用 `CHECKOUT_EXCHANGE=1`、新客户账号、全新购物车、商品浏览和履约模式；与退货退款及维修模式分开。生产开关仍默认关闭。

## 业务规则

0086将退款运行时提升为version3，旧worker拒绝执行。它保留原enabled值，不自动启用退款，不在应用启动时执行DDL。员工仍须具备独立退款权限、付款读取及售后写权限；付款仍来自本店实际成单receipt及原加密付款请求。

处理中exchange的全部明确原设备必须已经收回，并能关联本申请、原分配及已收货的原生换货/退货事实。当前商品金额与精确订单交易流水计算应退差额，缓存汇总不授予退款额度。所有付款、售后请求的未决退款占款一起扣除；同时保留原付款的实收扣已退/未决上限。

换机仅接受完整的当前可退差额，与“一申请一个成功指令”的约束一致；退货保留原有部分退款规则。发送前重新核对当前原申请、设备及换机差额，金额变化时指令保持未发送，可由员工明确取消再创建带前驱的新尝试。已发送指令继续原UUID的GET核实或保存观察应用，不因后续业务变化重新POST。原生换机差额未结清时不能审核完成。

现有售后表显示换机退款入口，沿用原Ant抽屉、原付款选择、精确字符串金额、指令历史和本地只读轮询；显示服务器核对的当前可退换机差额。取消和原指令重试在额度已被该指令占用时仍可用，避免以可退金额0错误禁止取消。中英文和手机/桌面布局沿用原实现。
