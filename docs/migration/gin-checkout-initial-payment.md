# 首次Mollie支付创建入口

2026-10-29。本次补齐从当前配送购物车创建首次支付会话的Gin命令及私有HTTP入口；原前台支付按钮尚未接入，支付/成单闭环仍未验收。

## 业务行为

原前台delivery继续按钮调用startMolliePayment，固定选择地区启用的`pp_mollie-hosted-checkout_mollie`，由后端创建集合/会话并跳转Mollie。现有新代码此前只实现旧会话删除/补偿，新入口`POST /api/store/carts/:id/payment-attempts`承接首次创建，JSON只接受version，操作UUIDv4来自Idempotency-Key。校验当前商店/渠道、凭证、Origin/CSRF、版本、限流及地区实际启用的支付提供商，不接受价格/提供商/回跳地址等客户端事实。

第一次执行重读地址、当前商品/价格、实际配送分组覆盖与仓库库存，刷新运费、税费及促销并重算总额。总额精确字符串和Mollie两位half-away结算金额分别保存；集合/会话使用结算金额，订单将必须保留原精确金额和明确舍入差额。当前零结算额拒绝，不能声称已完成零元订单。

0044新增默认关闭的checkout gate、当前购物车支付操作字段和不可变attempt。短事务一次性提交重算、版本递增、集合/会话、加密请求、操作绑定和冻结，再领取已提交的provider派发权。现有商品、地址、配送及旧支付刷新命令统一拒绝修改被冻结购物车；查询仍可读取当前草稿。支付适配器调用在SQL事务外进行，结果用独立短事务记录，即使原请求被取消也保存已授权的外部事实。

相同操作重放绑定当前归属/版本、集合唯一归属、唯一当前session、币种/精确金额、请求摘要和冻结字段。8并发只派发一次。创建结果未知不重新POST，不产生新幂等键；返回requires_review保留冻结。明确成功只投影已验证Mollie HTTPS checkout链接，原始provider payload、远程ID、密钥、request/context及代次不返回浏览器。session字段与请求/结果由独立业务keyring保护；成功后只激活一次，后续重试不重写加密会话或覆盖authorized/captured等状态。

## 配置和开放边界

`InitialPaymentOptions`必须由可信服务器代码显式提供独立Ring、已注册适配器、与实际前台Origin一致的ReturnOrigin和手动配送提供商。NewHTTP检查配置，复制提供商清单，默认无配置时503。尚未在cmd/api自动读取或启用真实支付配置，也没有新增前台bridge、付款返回页或开放付款按钮。这样保留可审查、可隔离运行的实际HTTP命令，后续应在返回核实、取消/过期解冻、库存预留、唯一成单和必要通知接通后统一开放。创建会话不代表已付款，也不代表已预留库存或成单。

已有支付集合不走首次创建分支；需接现有持久失效/补偿协调及已支付对账，不能静默替换。已有未提交0037 webhook收件箱改动保留，不夹带进本次提交，后续实际支付通知需要时复用。
