# Gin / React Admin 售后审核

本批接续客户售后申请，迁移旧业务的审核状态操作。订单详情使用 Ant Design 表格、状态选择与确认框；需要显式 `order.after_sales.write` 权限，并同时具备订单、支付和设备读取权限。仓库身份不能获得此操作。

## 业务边界

- 待处理申请可改为处理中、完成或拒绝；已完成、已拒绝申请不能重新打开。
- 已收回设备的申请不能拒绝。完成时检查原关联设备是否存在，以及检测、维修、维修完成等待处理等阻塞状态。
- 维修要求原设备已重新发货，换货要求对应替换设备已发货；带设备的退货要求存在关联申请的正数退款事实。
- 沿用原业务：没有设备条目的未发货申请允许完成。本次审核不执行退款、收回、检测、维修、换机发货，也不发送通知。
- 写入默认关闭。0069 迁移增加运行开关、审核收据和权限动作；不会自动向现有角色补发权限。提交后的迁移总数为 68，动作数为 26。

## 一致性与权限

写入在事务中锁定订单和关联事实，校验内容版本；过期版本拒绝覆盖。操作 UUID 绑定操作者、订单、申请和原请求。响应丢失后使用相同请求恢复结果；当前权限撤销或目标删除后，旧收据不能绕过检查。收据失败回滚状态变更。

前端首次提交需要确认；结果不明时冻结原目标状态并直接重试已确认的请求。重新读取后可核对最新事实，再决定下一次操作。

## 验证及限制

证据见 `after-sales-review-report.json`。独立 MySQL/Redis 中验证并发重放、晚期失败回滚、旧版本、撤权、软删除和关闭后重开保护，以及真实 Gin HTTP handler 的读取、重放和输入校验。客户 Astro → Gin 联合浏览器回归保留真实数据库；Admin 浏览器使用模拟 API 检查交互，不据此声称后台浏览器与真实 Gin 全链路通过。

本批仍不是完整售后闭环；后续需继续实际收回/检测/维修/换机/退款、通知邮件和全前台其他待验收流程。
