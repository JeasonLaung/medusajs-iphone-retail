# 回收申请创建

0074 新增原 24 字段的 `buyback_requests`，保留金额/raw、问卷设备快照、12 状态、历史、软删除和完整提交标识。活动客户/提交标识以完整值 SHA-256 索引约束，不截断历史文本；摘要冲突拒绝写入。新账号归属和提交回执另存 `customer_buyback_submissions`，显式绑定新 customer_accounts、商店和申请。历史 customer_id 或相同邮箱不建立新账号归属。

创建复用现有客户事务：MySQL 账户行加锁后重新核对 Redis 会话、启用状态、邮箱验证和认证代次。服务端从锁定账号读取邮箱，校验真实商店，再处理提交回执；需要新建时检查默认关闭的 `buyback_request_runtime`，在相同事务捕获当前商品/容量/报价，写申请、初始 submitted 历史及不可变创建回执。后续错误全部回滚，不调用支付、邮件或设备操作。

同一账号和提交标识的相同规范输入重放返回原创建结果，不重算价格、不新建设备项。内容或店铺变化返回冲突；不同账号的相同提交标识是独立申请。已有成功结果可在新建开关关闭后重放，账户禁用或会话撤销仍拒绝。回执目前保存创建时结果；未来状态变化后的详情读取需单独实现，不能将该回执当作当前状态接口。

Gin 新增 `POST /api/store/customer/buyback/requests`，使用既有私有响应、可信来源/Host、签名桥接（已配置时）、会话和 CSRF 保护，拒绝查询参数。JSON 上限 16 KiB，重复键、未知/别名字段及完整输入校验沿用已对照原 Zod 的解析器。成功返回 201，仅返回公开申请投影；店铺来自服务器 `STOREFRONT_STORE_ID`。Astro 客户桥接尚未放行该路径，表单尚未连接。

隔离 MySQL/Redis 直接执行 73 个正式迁移，通过 8 路并发同键仅一份申请/回执、不同内容冲突、跨账号隔离、写开关关闭、账户禁用、真实客户登录/退出后撤销重放、匿名拒绝、后续失败整体回滚。HTTP 验证成功 201、CSRF/来源/匿名/查询/重复 JSON 拒绝和公开字段边界。原公开报价与商品读取回归同时通过，独占容器已核对所有权后清理。Go 全量及 AdminAuthentication、InventoryStockEdits、ProductInventory 三组实库回归通过，旧 health/app/sell 返回 200。

当前尚缺 Astro 桥接/原问卷及提交表单联合、当前申请列表详情、照片存储/审核、设备关联、最终报价、确认、付款退回及邮件。没有修改生产数据库，也没有启用新回收写入开关；完整业务继续待办。证据和源码 SHA 见 [报告](buyback-create-report.json)。
