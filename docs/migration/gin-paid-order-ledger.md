# 已核实付款的订单实收账目

2026-10-29，C06 订单事务组件，接续 [快照](gin-paid-order-snapshot.md) 与 [库存预留](gin-paid-order-stock.md)。当前尚未开放完成结账接口。

## 已实现

`cart.StagePaidOrderLedger` 只接受已有SQL事务，重新检查当前凭证/版本/冻结付款、独占集合/会话、请求摘要和加密 `paid` 证据，并核对证据中的远端支付身份与不可变创建结果。仅授权、需复核或失败状态不能登记实收。证据校验从快照方法抽取为同包内部函数，两条路径复用同一规则；不提供接收客户端付款结果的通用接口。

目标订单必须是该购物车唯一的订单关系，版本1、非草稿、未取消的pending订单，币种和精确订单总额与冻结金额一致。订单原有结算关系/交易/汇总、既有支付（包括软删除）、已有集合授权/实收/退款余额均拒绝覆盖；未知部分状态交给后续恢复流程处理，不擅自修复。

同一事务写入支付、捕获、订单支付集合关联、指向捕获ID的订单交易和版本1金额汇总，再更新集合为completed、会话为captured。所有现金金额使用已核实的渠道结算金额；原订单和商品价格保持精确原值。集合退款余额显式为零，支付数据用独立付款行AAD加密，不能直接搬用会话密文。`captured_at`/`authorized_at` 使用本次本地登记时间；本组件未声称该时间是渠道实际结算时间。

这是将**渠道已确认的付款登记到本地账目**，不会发起远端capture、重新创建付款或实际发送邮件。重复调用会冲突，不会追加第二笔支付；已有会话活动支付唯一约束进一步保护写入。它没有取代最终成单收据：完整协调器仍必须先查询幂等收据，再在同一事务串联快照/预留/促销/账目/购物车完成/outbox，成功提交后才能向客户确认。任何错误都必须回滚整个事务，不能只回滚账目局部。
