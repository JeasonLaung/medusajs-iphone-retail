# 客户业务事件邮件与后台恢复

2026-11-03。补齐 C10 的业务事件投递链路。原 `customer-notifications.ts` 和回收工作流只写站内通知；订单确认已有独立加密 outbox。本批保留原站内通知行为，为新账号的订单/回收/售后事件追加邮件队列，不从可合并的站内通知表轮询生成邮件。

## 事务与收件身份

第105迁移新增 `customer_event_mail`、独立投递门闩与投递收据。订单的付款收到、退款完成、发货、配送、取消、售后处理/完成/拒绝通过现有 `EmitOrderTx` 在原业务事务入队，以事件种类和资源作为唯一身份；只接受已验证启用的新账号的显式订单归属。回收复用原通知触发点：要求重拍、批准寄出、收件、终价、平台申请退回、寄回、确认退回、付款登记及取消；照片批准和设备关联不发。每次平台业务更新有独立邮件行，站内未读合并不会吞掉邮件事件。客户自己的提交/接受操作没有新增回执邮件。

队列只存账号标识、业务引用和事件，不存明文邮箱或私密正文，不回填历史事件。发送前复核账号启用/验证状态及订单或回收显式归属；不通过历史邮箱相同继承身份。订单按原订单语言生成中英文内容；回收没有语言字段，目前用英文。邮件只包含已提交事件和业务编号，引导客户登录查看，没有私有照片、地址、验机备注、银行资料或授权链接。

## 显式独立投递

`go run ./cmd/send-customer-event-mail [--once]` 要求 `CUSTOMER_EVENT_MAIL_ENABLED=true`、持久 CUSTOMER/MERCHANT 密钥环、完整105迁移及后台批准的 Resend 发信账户。沿用业务订单邮件所选的最早启用账户。API启动不发信；Windows `start.bat` 只在显式开关开启时启动该worker，并按其专用PID和完整可执行路径停止旧worker。当前主预览未开启该开关。

与既有订单邮件相同：数据库全局门闩每秒最多领取一个；30秒租约；8秒渠道超时；事务提交后才调用固定Resend HTTPS地址；最多3次自动尝试、间隔一分钟、首试23小时内恢复。首次发送冻结正文并以 CUSTOMER 密钥加密、绑定行/列/用途，保存发信配置及收件地址摘要。重试保持正文与 `mail/ce_UUID` 幂等键，渠道丢响应不生成新消息。收件账号/归属/地址变化、发信配置变化及超时均停止并保留失败原因。

后台邮箱页新增客户业务邮件任务表，现有订单确认任务保留。使用 `mail.read/write` 授权、CSRF、严格JSON、页码边界；仅投影业务编号、事件、状态、尝试次数、固定错误码及时间。失败重新排队在23小时期限内保留冻结请求和幂等键，用客户端操作ID与审计回执恢复丢失响应，并重新检查当前权限。发信密钥、加密正文、收件人、渠道ID及摘要不返回后台。
