# 原结账配送步骤迁移

2026-10-29。当前完成手动固定运费的候选读取与选择，购物支付闭环仍未验收。整个前台验收范围继续见 [current-delivery-scope.md](current-delivery-scope.md)。

## 接口与事务

`GET /api/store/carts/:id/delivery-options` 在当前归属、商店渠道、地区、已保存联系地址下读取实际配送候选，按商品配送分组、服务区域、提供商与仓库连接、有效价格及当前库存过滤。公开投影只含名称/说明、配送组、送货或自提、精确金额及库存不足标记，不暴露提供商凭据、位置ID或原始data。读取不改表，库存观察不代表已预留。

`POST /api/store/carts/:id/shipping-methods` 仅接受version与option_id、UUIDv4 Idempotency-Key；校验购物车凭证、原站Origin、CSRF、限流与当前SQL归属。重复/未知字段、null、数字版本、价格/提供商注入、尾随JSON均拒绝。0043迁移创建默认关闭的独立命令开关，不在API启动运行DDL或开启写入。

同一事务重验当前商品、价格、选中配送组的仓库库存，更换该组配送方式，并刷新保留配送方式、税费与促销，重算精确总额，最后一次性提交递增版本及不可变操作收据。其他配送组可以逐个选择，所有必需组均有效才报告complete；complete不代表允许支付。并发相同请求只有一次新保存。版本冲突、无效选项、库存不足或收据写入失败不留下部分变更。已有支付集合时拒绝修改，等待接入现有渠道失效/刷新协调；现有未实现提供商或动态报价方式也不会被静默删除。

手动提供商仅由服务器`MANUAL_SHIPPING_PROVIDER_IDS`显式登记，默认空；HTTP请求和数据库命名不能代替已实现的提供商代码。当前仅执行手动固定报价，实际动态提供商需按已有业务接入后才可展示/选择。

## 原界面与恢复

正式Astro checkout的delivery阶段替换原暂缺错误态，复用原checkout CSS/i18n、送货/自提分区、单选、说明、价格及摘要。保留选择中的即时选中反馈，服务端确认后更新实际运费/税额/总额；库存不足禁用对应选项，每配送组独立单选。保留原继续支付按钮，当前支付未接通时禁用并显示原不可用提示，不生成模拟付款/订单。

配送、联系地址、加购与数量命令共用Web Lock，待恢复的其他命令阻止新写入。配送journal只存购物车/操作/选项ID、版本和恢复阶段，无邮箱、地址、价格、凭证或提供商数据。结果不明时刷新后仍显式重试同一操作，不能换选项覆盖；已确认但读取失败时只读恢复，不重复POST。地址/配送/摘要三份私有读取版本必须一致。未完成配送操作时返回编辑地址会先恢复配送。
