# 仓库员工库存入口

React Admin `/warehouse-inventory` 接专用 Gin `/api/admin/warehouse/access`、`/warehouse/locations/:location_id/inventory` 和 `/warehouse/locations/:location_id/inventory/:id/stock`。仓库员工菜单来自既有当前权限快照的 warehouse 主体，实际动作和仓库列表则由专用入口重查。现有全店快照仍无仓库主体的全店动作，`can()`继续只认可 employee，全店商品/订单/支付/授权管理接口不放宽。

专用授权投影只返回当前版本、三个已有受限动作和有效可见仓库的ID/名称；不返回所有仓库再由浏览器过滤。当前身份、启用角色、能力开关及范围在同一事务锁定读取。selected只关联该用户的绑定，空范围无仓库；all只列有效仓库。未知动作/模型或超出1000仓库上限失败，不静默截断。未具备任何操作动作时不返回仓库目录。

库存按指定仓库分页，每页50行，额外读取一行确定下一页，不泄露其他仓库总数。返回库存项ID、SKU/名称、库存层ID、原始精确数量及库存修订。只关联有效库存项和未删除库存层；不投影商品/变体全集、供应商、成本价格、metadata或预留拥有者。余额由库存减预留精确计算，不作为可售承诺。请求仓库不在当前范围时拒绝；不允许任意查询参数、重复offset或非规范offset。

库存调整复用原 `EditStock` 事务内实现，新增受限分支先执行 `CheckWarehouseTx`，再按仓库与库存层ID共同锁定目标行。库存层不存在或属于其他仓库均不提供可操作对象。按目标仓授权后仍核对该行归属，避免请求里填写有权仓库、实际修改其他仓库的库存。全店入口继续使用原授权检查，仓库用户不能绕专用入口使用它。

原能力开关、64位十六进制状态修订、操作UUID、精确18位小数、库存/在途绝对量设置、预留合计与历史冻结核对、父记录有效性、当前授权重查、不可变收据和全事务回滚保持复用。撤销动作、撤销仓库绑定或删除仓库后，先拒绝再处理旧成功收据；不能凭旧操作读取或重新执行。此次不改预留、设备、配货、发货或历史冻结状态。

界面使用 Ant Table、Radio、反馈和原StockEdit抽屉；原全店库存表单仅增加可注入保存函数，默认调用保持原入口。页面每次读取、分页和保存后重读专用权限，接口失败清除旧数据。只读隐藏编辑，空范围明确提示；数据包含其他仓库标识时响应验证失败。对丢响应保留同ID/同内容重试，409要求重新读取；不把精确数量转换成浮点数。无图表。

真实SQL/HTTP专项与原全店库存回归：`python retail/scripts/test-admin-auth.py --warehouses-only` 现运行AdminAuthentication、InventoryStockEdits、ProductInventory三套件，包含仓库名称地址、范围、新账号和库存用例。覆盖跨仓读写、错仓库存行、精确数量、50+1分页、重复保存、冲突、撤权/撤范围后的重放拒绝、末尾收据故障整体回滚、软删除仓库、CSRF/query与私有字段排除。保留旧全店库存调整和读取回归，使用53项已提交迁移，排除本地未提交0037通知代码。

合成API浏览器验证：`node tests/warehouse-inventory.browser.mjs`，覆盖受限菜单、库存分页、原抽屉保存、丢响应原请求重试、冲突、只读/空范围、跨仓响应拒绝、中英、手机宽度与加载失败恢复。这类响应不证明Gin联合，单独记录在 [汇总报告](warehouse-inventory-report.json)。

真实浏览器联合：`python retail/scripts/test-warehouse-inventory-joint.py` 创建独占人工MySQL/Redis与生产Gin进程；Ant页面创建新仓库账号并选定仓库A，独立浏览器会话登录、只见仓库A、读取/调整精确库存、刷新保留结果，直接请求仓库B/全店订单拒绝，再由管理员页面停用，新用户旧会话401并返回登录页。没有API响应模拟或绕过登录。中英与390宽度同时检查。

联合验证结束回查真实MySQL：目标仓由 `100.000000000000000001` 变为 `99.000000000000000001`，另一仓仍为 `999.000000000000000000`；库存操作收据1、仓库用户1、账号管理收据2且账号已停用。联合运行器确认这些事实后才写 [联合报告](warehouse-inventory-joint-report.json)。MySQL/Redis保持单核768/128MiB，仅生产Gin端口随机绑定127.0.0.1；专用19383浏览器代理，SQL和Redis不发布。桥接网络未限制外连；没有宣称TLS安全Cookie验证，结束按归属清理全部本次容器、网络和二进制。
