# 已付款订单保留付款时的优惠

修复付款成功后移除会员、修改优惠面额或新增自动优惠造成成单失败的问题。付款前仍使用当前会员关系和规则定价；付款已经冻结后，成单登记购物车已保存的优惠调整，不重新判断会员资格或生成新的折扣。订单与付款金额保持一致。

来源为本机实际安装的Medusa 2.21.2 `cart/workflows/complete-cart.js` 第481—508行：从商品和运费的已保存adjustments生成amount/code，交给`promotion/steps/register-usage.js`登记。`promotion-module.js`的registerUsage在锁内重读并核对当前限额及预算，不重新计算客户组资格或折扣方法。来源文件SHA及逐项结论见[报告](paid-promotion-snapshot-report.json)。此前Gin在此多调用了一次ComputeCandidates，上一轮测试又将该实现当作预期；本轮以实际来源纠正该差异，不将此前较严格的行为视为业务要求。

Gin仍要求已认证的同一付款、购物车版本/持有者、精确金额及当前库存；从有效商品/运费调整读取正数raw金额，核对当前促销ID/code及购物车关联集合，再在原成单事务调用RegisterUsageOnce。当前促销身份/有效状态和预算锁仍保留。已耗尽额度或不可用配置映射为既有成单冲突409，不能当作成功或触发第二次收款。前台不能传入折扣金额、客户ID或渠道状态；没有新增API、DDL或页面样式。
