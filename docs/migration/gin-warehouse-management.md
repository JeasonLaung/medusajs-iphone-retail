# 仓库名称与地址管理

新 React Admin 的 `/warehouses` 使用现有 Ant Design Table、Drawer、Form、Input、Alert 和反馈组件，支持中英、列表、创建、编辑、刷新、只读权限和失败重试。原 Medusa Admin 与前台样式不变。界面结构核对 [Ant Table](https://ant.design/components/table/) 和 [Ant Form](https://ant.design/components/form/)；不增加独立图表。

Gin 私有 GET/POST `/api/admin/warehouses` 只返回有效仓库的ID、名称和地址字段，不透传metadata。新增 `warehouse.read` 与 `warehouse.write` 独立动作；查看需要read，写入同时需要read/write。迁移不向已有角色自动授予新权限；管理员标签不能代替授权。当前接口是全店员工管理入口，warehouse/supplier主体仍拒绝，不能拿这个列表当作仓库员工范围接口。

0052 增加默认关闭的仓库管理开关、全目录版本与不可变操作收据。写入在同一事务重查并锁住当前账号与权限，再锁仓库管理版本；创建生成新仓库ID，编辑必须读取有效仓库。国家必须在现有有效国家表存在；名称/地址限制长度与控制字符，邮编保留字符串。HTTP严格拒绝重复、未知、缺失、null字段、无效UTF8和尾随内容；既有管理会话、Origin、CSRF及请求体上限继续生效。

每次保存绑定原操作ID、原目录版本、操作者和完整请求。丢响应只重试原内容，不更换ID；成功收据重放不重复插入地址或仓库。撤权、停用账号或切换受限主体后，即使旧操作成功也不能读取其收据。目录版本冲突提示重新读取，确认成功前表单锁住，结果未知可以显式重试原操作。

地址采用写入新记录再切换仓库引用，保留原地址。源数据库约束禁止两个有效仓库共用地址，但软删除历史仓库可以保留引用；测试验证编辑有效仓库不会改写历史地址。仓库名称、地址、版本及操作前后快照在一个事务提交，收据插入失败整体回滚。接口不删除仓库、不改库存预留，也不自动配置销售渠道/物流供应者/服务范围。

隔离真实 MySQL/Redis/Gin 验证：51项已提交迁移、15项权限动作；4并发创建只产生一次新提交，HTTP同操作重放、编辑、历史地址保留、版本冲突、无效国家、缺失仓库、末尾失败回滚、只读权限、撤权后重放拒绝、warehouse/supplier拒绝、严格JSON及默认关闭。`test-admin-auth.py --warehouses-only` 可复现，资源为MySQL 1核/768MiB、Redis 1核/128MiB，无发布端口、无外部网络，结束按归属清理。
