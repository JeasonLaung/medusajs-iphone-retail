# 仓库已有包裹配货与换设备

仓库专用路径 `/api/admin/warehouse/locations/:location_id/orders/:order_id/fulfillments/:fulfillment_id/items/:item_id/allocation` 接受当前包裹行的设备选择，权限为 `order.fulfillment.read` 加 `warehouse.allocation.write`。候选限定同仓库、同 SKU、有效来源/渠道、可售且未被占用的设备；投影不含付款、成本、来源内部编号和无线身份字段。

复用原订单付款与配货资格检查，包裹必须属于该订单及仓库且未取消；新保存还要求订单有效、已付款、包裹未发货/送达。包裹行的 raw 数量保持权威，设备配货要求整数数量。每次保存限制在包裹容量及订单总数量内；不能跨仓库、跨 SKU 或重复选择设备。

选中的设备集合允许保留当前设备、填充历史包裹缺失的设备分配或替换当前设备。保留同设备不重复创建分配和设备事件；换设备保留原 assignment ID，并在同一事务恢复旧设备 available、把新设备变成 packed、更新来源并记录换机事件。填入已有包裹直接生成 packed 分配，**不再次扣数量库存**，不修改预留。请求减少当前分配数量会拒绝，因为原业务的“解除已装包设备”需要取消整个包裹及恢复库存，后续单独承接。

来源/设备身份锁保护事务，当前仓库权限、绑定和包裹关系在任何回执重放之前检查。操作 UUID 与 location/order/fulfillment/item、完整请求共同绑定到已有唯一回执表；结果未知重试保持同一个版本和正文，成功回执不重复执行。重放还要求分配和设备仍在当前包裹/仓库；同 UUID 改正文拒绝。

React Admin 在具有配货权限的仓库包裹详情提供 Ant 表格勾选控件，按序列号搜索、展示已选数量和包裹数量，使用独立版本并在成功后刷新商品/设备/发货状态。写入期间禁用编辑及其他包裹表单提交；结果未知时保留原请求重试。只读账号不显示该控件。
