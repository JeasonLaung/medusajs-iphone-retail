# 目录依赖子图的真实 MySQL 演练

固定 v2 快照的36张目录配置表涉及21,837行；递归父依赖还有9表1,722行，共45表23,559行。父表包括库存条目、仓库及地址、支付/履约 provider、配送区域和配送选项。复用严格字段计划计算闭包及拓扑顺序；分类自引用按实际父行排序，遇到循环或缺失即停止。

演练脚本 `retail/scripts/rehearse-catalog.py` 不接受应用DSN，不连接源库或生产服务器。只使用已有 mysql:8.4 镜像创建有独占所有权标签的临时实例：单核、768MiB、无网络、无映射端口，数据目录512MiB tmpfs，私有快照128MiB tmpfs。完整159表审查版DDL校验摘要后执行，外键保持开启；不是 LIKE 表结构的替代验证。

36表使用正式目录行组件，包含完整来源/目标账本及七类完整唯一登记。九张父表在本演练内使用严格整行转换和SQL逐列读回，仅支持验证目录关联；没有这些父领域的正式迁移账本、运行时或权限验收。

验证顺序为全流及关系校验、全部45表单事务插入并回滚、确认业务表与账本/唯一声明均清空、重新插入并提交、逐表核对行数，最后精确重放。重放前后在内存比较全部45张业务表及五张辅助表的完整有序字段指纹，包含首次尝试随机值，SQL NULL与非NULL分开编码。报告只写数量、代码/快照摘要和环境，不输出业务值或完整指纹。

全域375个已知历史引用缺口仍未解决，不能因为目录子图没有缺口就接受全量关系。36表中空表仍无真实行样本；普通JSON内资料/业务语义审查、正式schema、完整v2执行器、旧v1命令替换、全量恢复及Gin/React/Astro商品闭环尚缺。

执行：

```powershell
python retail/scripts/rehearse-catalog.py --snapshot logs/gin-migration/source-v2-20261027-payment-rows.ndjson
```

脚本结束按独占标签验证后删除临时容器和临时可执行文件；快照原件保留在Git忽略目录。执行证据将保存至 `catalog-mysql-rehearsal-report.json`，仅该报告成功存在并与实现摘要一致时才能引用通过结果。
