# 现有 SKU 编辑与颜色图库同步

2026-10-31：React Admin 商品详情每个 SKU 增加 Ant Design「编辑 SKU」抽屉，承接原 ProductEditVariantForm 的名称、完整选项、SKU/Barcode/EAN/UPC、材质、重量/尺寸、原产地/HS/MID 和管理库存/允许缺货销售。保留商品详情、价格、库存、设备追踪、图片管理的既有入口；更新后刷新商品与 SKU，支持中英文、键盘与 390px 窄屏。

Gin `GET/POST /api/admin/products/:id/variants/:variant_id/edit` 使用 0091 的独立默认关闭 `variant.edit` 能力、当前商品读写权限和不可变回执。既有 86 项迁移的固定 API 不显示新编辑入口。严格限定完整 JSON 字段和大小，拒绝重复/未知字段、非法 UUID/版本、非有限尺寸及重复或外商品选项；编码作为字符串保留前导零。公开付款金额不经过这里的浮点类型：只有原源模型本来为 DOUBLE 的物理重量/尺寸使用浮点，价格与数量未转换或重写。

## 原规则与事务

- 参考原 Medusa Dashboard `ProductEditVariantForm`、核心 `update-product-variants` 工作流、SKU 编号数据库触发器及 `iphone-product-images` 订阅者。选项需选择商品当前每个维度的一个有效值，不能引用仅存在于全局组但未分配给该商品的值。
- 核对并共用原组合碰撞语义：无选项商品可以有多个 SKU；有选项时，已有 SKU 包含同一完整组合即拒绝，不能借额外历史悬空值绕过碰撞。新建和编辑共用这项规则，输入仍要求完整当前组合。
- 编辑与新建先取得相同编号锁，再锁商品/SKU；选项、图库也锁商品。SKU/Barcode/EAN/UPC 全局活动记录唯一性、选项和图片版本在写入前重新核对。清空已有有效 ERP 编码保留其原身份；清空其他编码时分配新的 ERP，显式 ERP 预留高水位。已有库存项编码不随 SKU 普通编辑改写，与原更新工作流一致。
- 与原订阅者一致，只要当前机型/颜色有匹配图，SKU 图片关系同步为该颜色图库，首张 URL 为缩略图；保留匹配关系 ID、软删除不再匹配的关联。新颜色没有匹配图片时保留现有图片，不制造空图库。价格、SKU 身份、数量、预留和设备记录不随普通字段/选项编辑改变。
- 原库存开关语义一起迁移：关闭管理库存会软删除活动库存关联，保留旧库存项、数量及预留；开启且无活动关联时创建默认库存项和数量系数为 1 的关系，不凭空创建库存数量。已有活动关联保留。旧库存编码仍被占用时返回明确 409，不能自动挪用另一个库存项或历史库存。抽屉解释关闭及重新开启的影响；独立库存关系编辑仍需后续迁移。
- 商品字段、选项关系、图片、默认库存项、编号计数和最终回执同一 READ COMMITTED 事务提交。原 SKU 选项连接表没有软删除列，按其复合主键替换当前关系；前后快照保留在回执。末尾失败整体回滚。相同 UUID 绑定商品、SKU、员工和完整请求；重放仍校验当前权限，关闭能力后可恢复已有结果，撤权后拒绝。

## 验证

使用完整 91 项迁移、完整公开商品快照的独立本机 MySQL、受限用户、Redis 前缀及独立 Gin/React/Astro 端口。原源库和主试运行库保持不变，没有真实付款、退款、邮件或 Docker。

- 原生事务：4 个同操作并发只有一次新写入；字段、前导零编码和零尺寸保留；清空 ERP 保持编号；跨商品/SKU、过期版本、重复编码、重复/不完整/外商品组合拒绝；另一 SKU 不变。真实精确价格、库存量与 raw 数值、预留、设备身份/追踪记录前后逐字段摘要相同。
- 图库：红色改黑色同步两个匹配图及首张缩略图；无匹配蓝色保留当前图；末尾回执失败使名称/选项/颜色图/编号全部回滚。
- 库存：解除关联保留旧项；原编码冲突拒绝并回滚；使用新唯一编码可建立新默认库存关系；创建默认库存项后回执失败时新项和关系全部回滚。关闭能力恢复回执、撤权拒绝通过。
- 真实 Chrome 无 API mock：在抽屉编辑全部原基础字段、颜色/容量、缺货开关，保存并刷新；同 SKU 和 ERP 保留；重复请求恢复回执，重复组合 409；公开商品的精确价格仍为 `129.123456789012345678`，Astro 对应 SKU 的黑色图库正常解码，WebP 原字节 SHA256 一致；中英文与 390px 抽屉定位/横向溢出检查通过，浏览器脚本错误 0。
- 后端全包测试、Go vet、Admin TypeScript、差异空白检查通过。浏览器图片仅在独立 Astro 的专用公开目录准备，不写主前台的 public 或构建目录。

详见 [原生 SKU 编辑报告](variant-edit-native-report.json)。主实例仍使用既有 86 项迁移和固定 API；新能力尚未强行升级到主库。C03 的库存项关系管理、共享选项定义维护、条件价格以及完整业务联合仍待继续，整个 C01—C11 目标保持未完成。
