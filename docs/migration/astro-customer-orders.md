# Astro 新客户订单查询与成单关联

当前使用正式路由 /[countryCode]/account/orders、/[countryCode]/account/orders/details/[id] 和原付款确认页，接独立Gin客户会话，不调用Medusa。账号导航、近期订单和订单卡片的结构来源为原 account/overview、order-card、order-overview；详情框架来源为原 order-details-template，商品、地址、金额和付款块复用已迁移确认页。保留中英文、地区链接、原日期/币种显示及手机返回入口。本次不是全页同数据像素对照验收。

客户签名桥新增固定订单路由与canonical offset查询。签名包含完整RequestURI，因此分页参数也受签名保护。仅关联POST允许额外转发当前cart possession Cookie；列表/详情只转发客户Cookie，拒绝其他域、admin/Medusa凭证、未知参数和重复/畸形Cookie。客户端使用严格订单投影，拒绝private字段、混合/重复订单行、非字符串金额和无效日期；数量求和使用BigInt，保留128位小数支持。

付款确认页在存在客户CSRF提示时先检查真实客户会话及已有归属，再用双凭证POST关联本次订单。Cookie提示本身不授予权限。关联结果不明会显示“订单已创建，但尚未确认保存到当前账户”并允许重试；恢复先读取已有归属，已成功关联时不再次POST。访客原确认方式保留。已关联客户在确认页也可用账户权限读取，购物车凭证失效不影响其长期订单查询。

Gin新增客户详情GET，要求当前新账号有效且拥有显式customer_order_ownership关联。事务共用订单快照读取，核对完成收据与本地捕获款关系，不因cart会话撤销、cart active关闭或checkout gate停用而拒绝已归属客户。订单软删除/其他客户/客户会话撤销仍拒绝；不会按邮箱查订单，也不修改原orders.customer_id历史引用。列表增加SKU与原总额，卡片可保留原价划线。前端账号切换重置列表/详情，较早读取响应不覆盖较新的响应。

已验证：独立源码快照49项迁移、go test ./...，隔离MySQL/Redis OrderRead+CartRuntime（含双凭证关联、授权详情及购物车关闭后读取）；前端142项测试；Astro check 306文件0错误/0警告；正式Astro构建。实际Astro+合成API浏览器覆盖中英390/1440、HMAC全请求校验、关联丢响应和读取故障恢复且不重复POST、近期订单、列表/详情、SKU与精确158.75、空列表、失败重试、登录失效和无页面溢出；原账户注册/验证/地址及结账/付款/确认页浏览器回归通过。没有使用真实客户、外部支付或邮件。

仍缺真实Gin/MySQL与浏览器联合路径、真实支付成单与邮件收件、同数据样式对照；订单履约进度/付款退款状态的完整显示、评价、售后和原邮件订单转移尚未接入。页面显示这些缺口，不用假进度或成功操作代替。当前只承接新账号本次购买的订单关联，不开放历史邮箱认领，C02/C06/C07/C09仍未完整验收。
