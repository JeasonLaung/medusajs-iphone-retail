# 商品加购到付款成单的联合验证

2026-10-30：正式 Astro 商品页可以加购并跳转购物车，但 `GinCart` 未向已有 `CartTemplate` 传入结账地址，导致正式购物车的结账按钮始终禁用。已补上 `/checkout?step=address`；保存中、失败待恢复和恢复中仍不允许结账。没有修改页面样式和旧 Medusa 服务。

新增可选验证方式：`CHECKOUT_PRODUCT_BROWSE=1 python retail/scripts/test-customer-orders-live.py --checkout`，Windows 使用环境变量设置同名开关。依赖 Node >=22.23.4；可通过 `CUSTOMER_ORDERS_TEST_BACKEND` 指定隔离源码快照。

真实 Astro → Gin → MySQL/Redis 路径通过四组浏览器验证：英文/中文、390/1440 宽度，从商品页选择已有 SKU、点击加入购物车、刷新购物车保持商品、点击结账，依次提交地址、配送、付款及订单确认。支付页面先返回 pending，之后适配器确认 paid；刷新付款和确认页、重放完成请求均不重复创建订单。没有拦截业务 API 或预先添加商品行。

数据库复核四笔唯一订单、四次支付创建、每单一条库存预留操作与通知意图，实收每笔 158.75 EUR、合计库存预留增量 10。生产邮件 worker 的隔离 HTTP 通道共七次请求、四个唯一消息，未知结果自动重试和人工恢复继续通过。后续 SQL 回归通过，Astro 检查零错误、零警告（7 条提示）。临时容器、网络和测试程序已清理。证据见 [报告](shopping-joint-report.json)。

边界：每组使用生产命令建立的空购物车及测试凭证，尚未把首次匿名创建购物车或登录后购物车转移串入本次连续路径。商品为测试库商品，未以完整真实商品数据验收；尚未从首页/列表点入商品并串到仓库发货和客户物流。支付提供方及邮件最终 HTTP 为隔离替身，没有真实扣款或真实外部收件证据。本报告不能代表整个购物及售后业务全部完成。
