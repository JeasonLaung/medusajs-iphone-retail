# 先登录后首次加购的账户绑定

原创建购物车接口只创建匿名空车。客户先登录而没有购物车时，登录接管自然没有对象；稍后商品页创建新车后直接加购，会遗漏新账户归属，造成页面已显示组价而第一件商品仍按普通价保存。

现在沿用现有创建、账户接管和商品写入接口，在原商品加购协调器中增加持久准备与绑定阶段：创建空车→读取当前新账户→以唯一操作绑定→核验实际版本→加入第一件商品。仍使用同一个 Web Lock，不调用会再次获取锁的客户恢复观察器。绑定必须先于商品写入，重用服务端当前会话、CSRF、购物车持有证明和事务重算。

新增阶段保存在原 `retail.cart.intent.v1`，仅含业务标识、操作 UUID、输入版本和新账户标识，不保存邮箱、凭证或价格。创建、绑定、商品写入各自响应不明时，刷新后继续原阶段和原编号；确定绑定前不会加商品。绑定前再次核对当前账户，换账户或失去会话不能把未决操作交给另一个身份。原格式已有创建/加购/刷新记录继续可读。

仍受 `PUBLIC_CUSTOMER_CART_TRANSFER_ENABLED=true` 显式开关控制；关闭时沿用原行为。匿名会话仅确认当前没有账户，随后正常匿名加购，不提交绑定。待恢复的登录接管记录和新建车加购不会并行修改同一购物车。没有新增后端接口、数据库迁移或服务重启。
