# 新账号购物与订单归属连续验证

本次承接首次匿名购物联合：真实 Astro 注册新账号，未验证时登录返回 403、无登录会话；读取隔离测试库中加密验证邮件意图的链接，经正式验证页面调用生产 Verify，再通过正式登录页登录。随后从商品页创建购物车并加购、购物车跳结账、地址/配送/支付/确认，原确认页自动提交订单归属。

业务接口均使用生产 Gin/MySQL/Redis 实现，没有拦截注册、验证、登录、购物、付款状态或订单 API。支付提供方和最终订单邮件 HTTP 是隔离替身。验证链接由带随机密钥保护的测试端点读取，仅在 `_test.go` 编译的演练程序中提供，不代表真实邮箱收件。

设置 `CHECKOUT_PRODUCT_BROWSE=1`、`CHECKOUT_FRESH_CART=1`、`CHECKOUT_ACCOUNTS=1` 运行 `python retail/scripts/test-customer-orders-live.py --checkout`。新测试会话使用独立 Redis 命名空间；四组用例间仅清理该命名空间的登录计数，保留每组真实的八次限流策略，避免与前面的权限回归相互干扰。

覆盖英文/中文、390/1440：成单后账号可查看订单；移除独立购物车凭证后，游客确认接口 401，但账户订单列表和详情仍可刷新；另一新账号读取前一订单 404；退出登录后账户订单接口 401。同浏览器切换至上一新账号，当前订单 404，列表只显示该账号自己的订单。数据库复核四个已验证新账户的唯一归属及每单唯一 attachment 审计；付款/库存/订单邮件恢复和后续 SQL 回归继续通过。见 [报告](shopping-account-joint-report.json)。

没有使用旧登录账号或真实订单，没有依据同邮箱自动接管历史业务。尚不证明跨设备购物车同步或登录购物车合并，当前购物车仍由独立浏览器凭证持有。真实邮箱验证投递、真实支付、首页/完整商品目录与仓库发货到客户物流的连续验收仍待完成。
