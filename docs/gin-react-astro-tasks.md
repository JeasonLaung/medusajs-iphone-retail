# Gin + React + Astro 迁移任务清单

日期：2026-10-26；实施更新：2026-10-28。状态：基线、底座和商品闭环进行中，尚未完成全量验收。

## 当前实施范围（用户确认，2026-10-29，优先于后文全量历史计划）

本阶段目标为 **整个现有前台的功能闭环**，以及支撑前台和实际运营的后台：商品、SKU、仓库、仓库用户、库存、配货、通知邮箱。不是只保留购物/回收页面，也不是继续逐项迁移所有独立后台工具。详细排期与验收依据见 [本阶段交付清单](migration/current-delivery-scope.md)。后文原T任务、历史证据和未完成记录保留作参考；它们不能自动扩大当前实施范围。

- 前台所有现有页面、数据、操作、错误/恢复/权限状态均在范围内；首页、搜索、商品、购物车、结账/在线支付、账户、订单/售后、回收、评价及公共内容/多语言/导航均需真实可用。原页面结构与交互不改版。
- 后台除用户明确列出的模块，还须完成使这些前台流程走通所必需的订单处理、回收审核/报价/付款记录、售后处理、价格/配送/税/优惠配置及交易通知；不能把必要依赖延期造成前台断链。
- 独立营销群发/CRM、独立供应商门户、AI/SEO生成工具、与上述流程无关的运营统计等移入后期待办；前台已有的公开内容展示和必要供应来源/设备身份/订单关系并不因此移除。
- 停止按测试数、数据库表数或底层辅助函数推进范围；每轮围绕一项用户可操作的端到端交付，验证页面→Gin→MySQL→后台/通知结果。
- 旧登录账号不迁移，新客户与仓库员工重新建立；MySQL+Redis、Ant组件/ECharts、旧服务可用、不操作服务器等原约束继续有效。

## 目标与执行边界

- 最终架构：Go/Gin 后端、React 管理后台、Astro + React 前台；用户已确认使用独立 MySQL + Redis。
- 旧客户及员工账号不迁移，密码、会话、验证/重置令牌及个人登录权限不继承；新系统重新注册客户并创建员工账号。历史交易的必要联系信息、原客户/操作人标识及归属证据作为历史记录保留，不生成可登录的旧账号，不按相同邮箱自动绑定新账号。
- MySQL 是业务事实和交易一致性的持久化来源；Redis 用于缓存、限流、会话等临时状态。缓存丢失可恢复，会话丢失要求重新登录；库存、付款、幂等结果及可靠任务状态不能只存 Redis。
- 本阶段承接当前范围内的实际业务、必要历史数据与关联，不保留 Medusa 运行时依赖；其余独立后台业务后期迁移，不以“全部迁完”作为本阶段交付门槛。
- 管理后台仅参考 `iphone0902` 的布局和基础管理模式；零售交易、设备、售后、回收规则来自本项目。
- 2026-10-27 用户指定：新 React 后台优先复用 Ant Design 组件，图表统一使用 Apache ECharts。适合的表单、表格、布局、导航、弹窗、抽屉、上传和反馈不另造基础组件；业务逻辑保留，前台不受此组件选型影响。
- 前台严格保留当前页面、URL、文案、字体、图片、布局、响应式和交互，不借迁移改版。
- 当前阶段先完成任务与契约；不操作宝塔服务器，不部署、不切流，不改现有业务库。
- 现有开发服务继续提供行为对照。新实现只能连接隔离数据库；测试不改变真实订单、库存、设备或付款。
- 基线为 `dev@4bddaf5`，工作分支为 `codex/gin-react-astro`。基线之后的业务修改需要登记并同步，不能静默遗漏。

详细源码证据见 [迁移盘点](migration-inventory.md)，设计背景见 [架构分析](gin-react-astro-migration-analysis.md)。本文件管理执行顺序和完成标准，不替代字段映射、API 契约及测试报告。
